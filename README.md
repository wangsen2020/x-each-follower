# XFollower · 粉丝管理 · v1.0.8

## AI 协作与开发规范（开始前必读）

本节是 Codex、Claude、Antigravity、Grok 等 AI 协作者的项目级约定。开始分析或修改前先读本节及相关功能代码；任务提示与本节冲突时，遵循用户最新的明确要求，并及时更新文档。

### Git 与协作

- 动手前检查当前分支、工作区状态、远程分支和已确认的生产基线；不要假设当前分支就是生产版本。
- 不在 `master`、`main` 或 release 分支上开发。功能和修复在基于已确认基线的隔离 feature 分支中进行；当前用户明确允许直接在 `develop` 持续开发时，按该授权执行。
- 不为切分支而覆盖、重置或混入其他人的未提交改动。只提交自己负责且已检查的文件，不要把其他代理的改动一起提交。
- 用户已要求及时提交自己完成的代码；提交前检查 diff 和 `git diff --check`，提交信息简洁说明改动。未经用户要求，不推送、合并或发布。
- 多代理并行时，各代理先确认负责文件与边界；Codex 负责整合审查与验收。发现其他代理的改动有问题，应反馈给对应代理，不要擅自覆盖。

### UI 与 CSS

- 优先使用 flex 布局，并用明确的 `padding`、`margin` 控制间距；谨慎使用 `gap`。普通列表行默认约 `10px` 间距，通常不超过 `20px`，除非有明确的视觉理由。
- 禁止用 `!important` 修补样式。通过更具体、合理的选择器和组件作用域解决优先级问题，避免无边界的全局覆盖。
- 同一工具栏或操作组内的按钮高度、内边距和对齐方式要一致；图标按钮与文字按钮并排时也要保持同高。输入框、下拉框、按钮和下拉箭头需在同一行正确对齐。
- 页面内容区、表格行、段落与容器要有一致的基础留白，避免意外的空白区、文字换行或图标错位。修改布局后检查实际渲染效果及计算后的间距；仅凭 CSS 源码或截图局部不能认定全局问题已修复。
- 保持现有简洁、紧凑的视觉体系；新增控件应与同一页面已有控件在尺寸、色彩、圆角和交互反馈上协调。

### 功能语义与验收

- “互粉追踪”功能名称使用“互关追踪”；“评论追踪”名称及其独立功能保持不变。修改一个模块时，不要顺带重命名或改变另一个模块的语义。
- 优先使用可验证的页面网络接口获取数据，避免不必要的模拟点击；接口是否可用必须实测，不能只凭推测下结论。涉及关注等写操作时，严格遵循用户明确的产品流程与确认条件。
- 对扩展功能按完整链路验收：用户输入、界面事件、后台请求、响应解析、数据持久化和页面展示。分别说明代码检查、自动化测试、真实浏览器验证完成到哪一步；HTTP 成功、单元测试通过或静态检查通过，都不能单独代表用户功能可用。
- UI 修复应在真实扩展页面检查受影响的页面与状态。若登录态、浏览器权限、CDP 或其他环境问题阻止实测，应准确说明未完成的验收环节，不要声称已验证。
- XFollower 的 CDP 接入先运行 [tools/cdp-session.ps1](tools/cdp-session.ps1)：脚本会核对固定登录 profile、9222 端口与扩展目标；已有实例时直接附加。具体操作边界见 [AGENTS.md](AGENTS.md)。
- 新增设置、状态和持久化数据时检查升级兼容性；不能仅修改新用户默认值而忽略已有用户的数据迁移。

### 协作者交接

- 被分配实现任务的代理应报告改动文件、行为变化、验证结果和未完成事项；不要宣称未运行的测试或未观察到的浏览器结果。
- 向 Antigravity 或 Grok 分配 UI 工作时，提示中必须重复本节的布局规则（flex、谨慎使用 `gap`、行间距约 `10px` 且通常不超过 `20px`、按钮同高、禁止 `!important`）及真实页面验收要求。

品牌界面：XFollower。默认打开“粉丝管理”：粉丝与待回关使用两个列表 tab；可多选或全选，最多选择 20 个账号提交 Grok。账号的 profile、粉丝/关注数与最近帖子按 handle 写入本地缓存和 X 站点 IndexedDB，后续分析优先复用缓存，避免重复抓取。

界面采用左侧导航、右侧工作区的管理后台布局。默认“粉丝管理”把“粉丝”和“待回关”放在同一个列表页的两个 tab；列表支持按账号、名称或简介搜索，并以 20、50、100 条分页展示，便于累积管理大量历史数据。说明放在感叹号 hover 提示中。

当前版本：`1.0.8`。在 `chrome://extensions` 中重新加载扩展后，可通过版本号确认已载入新版本。

Grok 针对候选用户近期帖子生成的互动评价以 X 的“引用”形式发布，保留原帖卡片并出现在自己的帖子时间线上。发送前会校验引用编辑器确实嵌入目标原帖；X 文章卡片没有直接状态链接时，会结合目标帖子页、作者和文章标题识别，目标不匹配则停止发布。

引用评价提示词会优先从原帖细节中寻找反常识、隐性代价或两难角度，写出鲜明但有依据的观点；可以用夸张比喻增强表达，不编造或夸大事实。

设置按功能放在各自页面的齿轮抽屉中：粉丝管理配置粉丝检索，互关追踪配置自动看帖与关注，评论追踪配置评论用户处理，回关监测配置回关检查与操作。当前没有需要跨功能共用的全局参数，因此不保留独立的左侧“设置”页；已有的旧版筛选记录仍保留在本地存储中。

“互关追踪”以一个互粉锚点为入口，分别静默读取该账号的 following 和 followers，合并、去重后展示为可追踪的账号网络。支持按账号、名称或简介关键词筛选，支持全选、多选定额执行“批量更新”与“Grok 分析”，并提供定时获取有意向有价值用户、自动打开主页下拉浏览帖子后点击关注的设置能力。网络数据同样写入扩展存储和 X 站点 IndexedDB。

点击粉丝列表的“资料”会在当前页面右侧打开资料抽屉，不跳转主界面。抽屉优先展示持久化的画像缓存；尚无缓存时会静默打开并关闭后台 X 标签页，读取公开 profile、头像、粉丝/关注数和最近 5 条帖子。“采集资料”可手动刷新缓存，也可在可见 X 标签页打开主页。

候选账号行新增“打开并关注”按钮。点击后会在最小化后台窗口打开对方主页，只在确认页面按钮为精确的 `Follow` 时点击；已是 `Following`、`Follow back` 或 `Pending` 时不会重复操作，也不会抢当前窗口焦点。

待回关列表会把 `Follow back` 排在最前，并提供独立的待回关展示区；扫描过程中已经发现的待回关账号会先进入队列，不必等到所有粉丝都滚动完才知道结果。待回关 tab 的每一行有单独的“回关”按钮（已关注 tab 没有）。点击后会打开最小化、不抢焦点的 Chrome 窗口到 `https://x.com/<handle>`，只在主页按钮精确为 `Follow` 时点击；成功后把该队列项标为已回关并写回本地。若已是 Following / Follow back / Pending，则不再点击，并按已回关移出待回关。若页面出现 rate limit 一类限制，则不改状态，并暂停约一小时。

粉丝读取优先使用 X 页面自己发出的 GraphQL 请求模板。`net-hook.js` 在页面主世界被动捕获 `Followers`、`Following` 和 `UserByScreenName` 模板，`bridge.js` 只把模板元数据传回扩展；扫描时在同一个 X 页面上下文中复用模板发只读请求，成功时不需要滚动或逐个解析用户卡片。模板尚未捕获或 X 接口结构变化时，插件自动退回 DOM 列表读取。

## 新增：粉丝监测与回关队列

工具页现在包含“定时检查我的粉丝”模块。它会打开 X 的全部粉丝页，滚动读取可见粉丝卡片，识别卡片上的 `Follow back` / `Following` 状态，并把待回关账号保存在本地队列。你可以设置检查间隔、每批最多处理数量和批次间隔；点击“处理待回关”后，插件会按队列执行页面上的回关操作。若页面出现“unable to follow”“rate limit”“try again in an hour”等限制提示，插件会停止本批并记录约一小时后的暂停时间，避免重复尝试。

在粉丝或待回关 tab 内选择账号后，可直接点击“Grok 分析”。支持单选、多选和全选，一次最多 20 个账号。插件优先读取已缓存的 profile、粉丝/关注数和最近最多 5 条帖子；只有尚未缓存的账号才会在后台标签页中读取，画像会保存到本地和 X 站点 IndexedDB。

点击列表中的“Grok 分析”时，插件会创建一个不抢焦点的最小化 Chrome 窗口，打开 `https://x.com/i/grok`，把整批提示词填入 Grok 输入框并点击发送。若 Grok 页面改版、输入框未加载或登录状态失效，插件会把完整分析包复制到剪贴板，并在工具页报告原因，避免资料丢失。

粉丝扫描还会运行本地危险信号规则，检查成人平台、擦边色情、私密内容导流、博彩、付费解锁、Telegram/微信导流和可疑外链等公开文字。命中后标记为“危险”，不会进入回关队列；这只是保守的关键词提示，不等于对账号的事实判断。危险账号仍可在 X 主页上人工确认和屏蔽。

定时检查只负责提醒和扫描；队列和处理进度保存在 `chrome.storage.local`。首次扫描会读取当前可见列表作为本地状态，后续扫描会保留已经处理过的账号。X 页面结构、账号状态和限制提示可能变化，因此每批开始前请确认当前浏览器仍登录了正确的 X 账号。

Chrome / Edge Manifest V3 插件。从指定用户的 following 列表收集账号，**逐个导航到真实 profile 页面**，读取名称、简介、粉丝数与关注数，寻找可人工复核的互关线索。不调用 X 私有接口、不接入外部 AI、不上传资料、不自动关注或取消关注。

## 安装与使用

1. 下载此仓库并解压，或克隆仓库。
2. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`，打开开发者模式，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的目录。
3. 在同一个浏览器中登录 X，然后点击插件图标，打开工具页。
4. 输入目标用户名（例如 `@username`）或 profile 链接。目标可以是你关注的某个用户，但插件不会验证你是否已关注此人。
5. 设置检查数量、人数比例、最低人数、访问间隔，点击“开始查看资料”。插件会打开检查标签页；请保持工具页开启，并避免手动导航检查标签页。
6. 筛选结果，点击主页链接复核，或导出全部记录为 CSV。停止后保留已完成记录；关闭工具页会终止本轮，重新打开可查看已保存结果，但不会自动续跑。

## 如何判断

默认比例为 **粉丝数 / 关注数 0.7–1.4**，两项人数至少为 50，并要求名称或简介包含互关、回关、follow back、F4F 等描述。这些阈值只是可调整的个人筛选规则，没有经过回关率统计验证。

| 结果 | 含义 |
| --- | --- |
| 候选 | 资料可读，符合人数与比例条件，并满足所选的简介条件 |
| 承诺与比例不符 | 名称或简介有相关描述，但人数比例不满足设置 |
| 需复核 | 资料不可读、人数无法解析，或关注数为 0 |
| 未命中 | 可读，但不满足其他候选条件 |

这些信号不能证明某人“骗关注”，也不能保证会回关。插件不核验目标用户与候选之间的双向关系，也不将 X 的“关注了你”标签当作对所有人的互关承诺。简介正则可能命中否定描述（例如“不互关”或“no follow back”），需要人工阅读上下文。人数缩写（如 1.2K / 1.3万）按展示值估算，不代表精确人数。

## 读取范围和限制

- 仅解析页面实际展示的 following 用户卡片和 profile 人数链接，不采集帖子、推荐区计数或隐藏资料。
- following 列表会自动滚动，最多检查 500 个账号；连续 8 轮未出现新账号或最多 150 轮滚动后结束收集。只代表本轮可见账号，不保证是完整列表。
- 默认每个 profile 完成后等待 5 秒，可调范围 3–60 秒。连续 3 个 profile 无法读取时停止，不绕过登录、验证码、访问限制或私密账号限制。
- X 可能调整页面 DOM；选择器基于 `primaryColumn`、`UserCell`、`UserName`、`UserDescription` 和 profile 人数链接。页面变化可能需要修改 `page-reader.js`。
- 此版本通过本地逻辑及模拟 DOM 检查；尚未在用户已登录的真实 X 会话中完成端到端验证。

## 数据与权限

仅请求 `scripting`、`storage`，以及 `https://x.com/*`、`https://twitter.com/*` 的网站权限。`scripting` 用于读取已加载页面，`storage.local` 保存最近一轮结果和设置。插件通过浏览器已有的登录会话访问页面，不读取或导出 cookie、密码、令牌；代码无外部上传请求。点击“清空记录”删除本地结果，设置仍保留；卸载插件可移除扩展存储。CSV 由用户手动导出，需自行保管。

Chrome 官方文档：[scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)。X 官方帮助：[following 常见问题](https://help.x.com/en/using-x/common-following-issues)。

持久化：历史队列、账号记录和 Grok 分析资料会同步写入 X 站点下的本地 IndexedDB。扩展重装后，只要没有清除 x.com 网站数据，重新加载插件即可恢复；扩展的 `chrome.storage.local` 仍作为快速缓存。
