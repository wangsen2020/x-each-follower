# 文档自动沉淀与时间顺序归档指令 (doc)

本指令用于在项目迭代、架构改造、功能新增或重大排障后，规范化总结并沉淀文档至 `docs/` 目录。

---

## 一、前置判断：是否值得新建或写文档？

1. **值不值得写文档**：
   - ❌ **不写文档**：单行修复、typo、配置项微调、小样式微调等琐碎改动；
   - ✅ **写文档**：架构调整、跨文件重构、重大排障复盘（如 CDP 排障定位）、新模块或新功能等有复用价值的改动。
2. **新建 vs 合并的判断标准**：
   - **禁止无脑追加新建文件**！
   - **同天 / 同会话**：只要和最近一篇文档主题相关（哪怕标题不完全一致），**一律在已有文档内改写补充、融合或追加小节**；
   - **仅在以下情况新建文档**：跨天、跨独立模块、且与现有任何文档都不相关的实质性全新变更。

---

## 二、命名规范与格式约束

1. **文件命名格式**：
   ```text
   序号. 简要描述_日期_时间_{git用户名}.md
   ```
   - 序号后带空格（如 `5. 排障复盘-...`），与现有文档编号递增保持一致；
   - 日期时间：自动获取当前实际时间（格式如 `YYYYMMDD_HHMM`）；
   - git用户名：自动通过 `git config user.name` 获取（如 `wangsen`）；
   - **硬性禁止 ASCII 特殊字符 `( ) [ ]`**（防止截断 Markdown 链接），需要分隔时必须统一使用中划线 `-`；
   - **中文命名偏好**：所有文档标题和分类目录必须使用中文命名。
2. **功能迭代分类存放**：
   - 如果有相同功能的迭代演进，在 `docs/` 下对应分类文件夹存放（如 `docs/互粉与粉丝管理/`、`docs/画像与标签系统/` 等）；若属于全新分类模块，则新建对应的中文目录。

---

## 三、文档时间顺序对照表维护规范

每次沉淀文档后，必须更新当前作者对应的对照表：`docs/文档时间顺序编号对照表_{git用户名}.md`。

1. **可点击相对路径格式（必须严格遵守）**：
   - **必须以 `./` 开头**（相对于 `docs/` 目录），禁止使用裸路径；
   - **路径中的空格必须转义为 `%20`**（确保 CommonMark/WebStorm/GitHub 均可直接点击打开）；
   - 正确示例：`[5. 关注异常排障与接口修复_20261016_2205_wangsen.md](./互粉与粉丝管理/5.%20关注异常排障与接口修复_20261016_2205_wangsen.md)`；
   - 错误示例：`[5. xxx](互粉与粉丝管理/5. xxx.md)`（缺 `./` 且空格未转义）。
2. **表格列顺序规范**：
   - 可点击链接列**必须**紧随「序号」列之后，即全表除序号外的第一列，说明/标题放在链接列之后；
   - 标准列序：
     ```markdown
     | 序号 | 文档 | 说明 | 创建时间 | 分类 |
     ```
   - 新增记录必须严格按此列序追加，严禁将链接与说明位置颠倒。
3. **全局时间编号顺序**：
   - 检查 `docs/` 下所有历史文档的创建时间，确保全库文档序号 `1. 2. ... N.` 递增有序，清晰反映演进路线图。

---

## 四、执行步骤

当用户触发 `/doc` 或要求总结沉淀文档时，按以下流程执行：

1. **获取环境信息**：
   - 执行 `git config user.name` 获取当前用户名；
   - 获取当前系统本地时间（YYYYMMDD_HHMM）；
   - 检视近期 git commit 历史与代码改动（`git log -n 5`，`git status`）。
2. **评估合并与归档目标**：
   - 检查 `docs/` 下最近的文档，判断当前改动是否属于现有主题的补充与演进；
   - 若可合并，在对应文档中补充小节并更新内容；
   - 若确需新建，按命名规则确定文件名与目标分类目录。
3. **编写/更新文档内容**：
   - 包含背景、根因定位、解决思路、关键代码对照及验证测试数据。
4. **更新对照表**：
   - 更新 `docs/文档时间顺序编号对照表_{git用户名}.md`，核对 `./` 与 `%20` 转义链接，检查列序。
5. **汇报结果**：
   - 向用户清晰汇报更新了哪篇文档，以及对照表追加的记录与可点击链接。
