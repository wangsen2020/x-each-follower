1. 将近期的改进总结一下，写到 docs/目录下
2. 命名规则 `序号. 简要描述_日期_时间_{git用户名}.md`，日期时间记得自己获取（序号后带空格，与现有文档一致）。**但禁止 ASCII 特殊字符 `( ) [ ]`**（`)` 会提前截断 Markdown 链接），需要分隔用中划线 `-`。
3. 另外根据创建时间，将 docs 下的创建时间，标题顺序增加序号，如 1. 2. ... 21. 方便识别文档创建的时间先后
4. 你不要每次执行这个命令时都无脑进行文件追加，若是最近几个文档的补充和融合，你就还在之前的文档中改写补充融合即可,否则会造出来很多多余的文档
   - **新建 vs 合并的判断标准**：同一天 / 同一会话内产生的改动，只要和最近一篇文档主题相关（哪怕标题不完全一致），一律在该文档追加小节，禁止仅因为标题措辞不同就新建；只有跨天、跨模块、跟现有任何文档都不相关的实质性变更才新建
   - **值不值得写文档**：单行修复、typo、配置项微调等琐碎改动不必执行本命令；只有架构调整、跨文件重构、排障复盘、新功能这类有复用价值的改动才值得写
5. 每次更新 `docs/文档时间顺序编号对照表_{git用户名}.md` 后，**必须**为每条记录追加可点击的相对路径，否则我不能直接点开。路径硬性要求：
   - **一律以 `./` 开头**（相对 docs/ 目录），不要写成裸的 `分类文件夹/xxx.md`；
   - 路径里的空格转义为 `%20`（标准 CommonMark，GitHub/预览/WebStorm 2023 均可点）。注：WebStorm 2025 有已知缺陷不解码 `%20` 导致点不开，属该 IDE 版本问题（可降级或用 2023），非文档问题；
   - 正确示例：`[179. xxx_20260607_2047_wangsen.md](./AI能力/179.%20xxx_20260607_2047_wangsen.md)`；
   - 错误示例：`](AI能力/179.%20xxx.md)`（缺 `./`）；
   - 同一规则也适用于文档正文内对其它文档的交叉引用链接，写完务必逐条核对。
   - **表格列顺序**：可点击链接必须放在「序号」列之后紧邻的一列（即链接是全表除序号外的第一列），说明/标题等纯文字放在链接列之后，例如
     `| 序号 | 文档 | 说明 | 创建时间 | 分类 |`（`_senzo.md` 因历史遗留多一列「时间顺序」时则为
     `| 时间顺序 | 序号 | 文档 | 说明 | 创建时间 | 分类 |`）；新增行严格按此列序追加，不要把链接和说明顺序写反。
6. 由于单一的`docs/文档时间顺序编号对照表.md造成的合并冲突较多，建议按照文档时间顺序编号对照表_{git用户名}.md
7. 保证谁的的工作谁负责，但整体路线图是清晰的
8. 若你整理docs文档时发现没有中文命名的，请顺手更改成中文命名，记住这个偏好
9. 如果有相同功能的迭代，就新建文件夹，进行分类存放
