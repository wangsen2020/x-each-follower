# Bot任务即时检查点与队列引用发布验收

## 问题与范围

本轮要求将关注队列连接到已验证的Cloudflare与Grok Bot回传通道，串行完成一条引用发布，已有生成结果不得重复请求。

现场发现Sanwanyingchi23与TylerBai_loveai两条本地Bot任务仍为accepted，但Worker查询均已completed；对应队列评价在评论执行中断后成为uncertain，relayJobId却为空。原实现只在generate返回pending时保存ID，任务创建至结果返回之间存在检查点空窗，中断后无法按原ID自动续查。

## 修复

- `grok-bot-relay.js`为generate增加onJobCreated检查点：先保留本地任务，再通知所属队列保存ID，成功后才允许POST发出。复用未交付任务时同样通知所属队列；检查点失败不发起付费生成。
- `grok-comment.js`把队列提供的onRelayJobCreated传递到通道生成器，保留已有relayJobId直接resume的路径。
- `follow-queue-runtime.js`立即保存relayJobId、grok-bot通道及bot_pending状态。结果仍由原生成器解析并保存，发布继续经过现有账号、原帖和防重复核验。
- `comment-worker.js`在已有Bot检查点、未收到正文时保留uncertain，供原任务续查；不重放生成。

使用现有Dexie存储、resolveJob和通道路由，没有增加数据库迁移、Worker兼容层或新依赖。
