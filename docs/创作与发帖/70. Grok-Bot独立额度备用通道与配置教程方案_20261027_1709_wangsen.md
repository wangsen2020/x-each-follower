## 目标与验收边界

当 X.com Grok 在发送前明确报告聊天额度耗尽时，XFollower 使用用户在 grok.com 网页端配置的 Webhook 自动化生成文本。用户照图配置网页任务、Cloudflare Worker 和 D1，最后在插件填写 Worker 地址与专用连接 Token，即可启用备用通道。教程提供完整固定代码、配置步骤、排错、截图，以及可整体复制给 ChatGPT 或 Claude 执行的指令。

用户截图显示每周 SuperGrok 与每周 Grok Bot 两个独立使用量计量项。用户在实施中再次确认：回调配置入口是 grok.com 网页端自动化，执行者不要求是指定的“互粉”Bot。本轮据此采用已跑通的网页任务入口，教程不要求操作桌面 Bot。端点可执行与计入哪项周额度是不同证据：运行记录和回调可以验证生成闭环，但不能单独证明额度计费池；整数百分比不变时不声称零消耗，也不通过大量请求人为制造百分比差异。

## 已研究的复用方案

1. Cloudflare 官方 Workers、D1 binding 与 Wrangler 用于部署、事务保存和运行环境，不自行开发部署平台或数据库封装。
2. Standard Webhooks 官方开源 JavaScript 库 standardwebhooks 用于签名；评估 MIT 许可证、Workers 的 nodejs_compat、依赖体积和签名 API 后优先复用。若 Bot 实际协议与普通 Automations 不同，按实机协议调整，不能假设共用端点。
3. 插件复用 Dexie 的连接与事务能力，在独立的本机数据库 xfollower-grok-bot 保存连接和任务；凭据不进入业务记录备份。复用 Vue 现有系统设置、tips 与父级焦点管理，不另造完整设置系统。
4. 仅编写项目特有的任务状态、幂等提交、Bot 回调认证与原文结果适配。保留现有质量门禁、身份核验和发布逻辑。

## 数据流与配置

1. X.com Grok 返回明确 quotaExhausted；一般网络错误、验证码、取消、身份不符、未知生成结果不得据此自动切换并重复执行。
2. 已绑定且启用的备用通道生成稳定 jobId，先保存本地检查点，再 POST /v1/jobs。正文为 jobId、prompt；Authorization: Bearer 使用本次连接专用 Token。
3. Worker 持久化 jobId、promptHash、状态和一次性回调 Token 的哈希，在写入成功后才签名触发 Bot 的 webhook。重复 jobId 且 prompt 相同只查询原任务；正文不同返回冲突。网络中断保留 unknown，不盲重发。
4. Worker 沿用既有实测的字段 jobId、text、callback、callbackToken；完整 prompt 放入 text。网页任务按 text 生成文本，回调 URL 固定在任务指令内，动态内容不能更改目的地。生成完成后 POST /v1/callback，字段 jobId、token、result；token 来自本次 callbackToken。
5. Worker 检查 jobId、Token 哈希、结果大小及状态，原子写入 completed。相同结果重复回调返回成功，冲突回调拒绝。凭据和 callbackToken 不出现在查询响应中。
6. 插件每 30 秒 GET /v1/jobs/:jobId，带连接 Token；完成或确定失败后停止。等待超时保留任务和提示词，重新打开可按原 ID 恢复，不自动再次创建。
7. 生成结果进入现有文本解析与质量校验。此服务仅生成文本，不能自行触发关注、私信、删除或公开发布。

Worker 环境：DB 为 D1 binding；WEBHOOK_URL 为目标 Bot webhook；WEBHOOK_SECRET 为签名 secret；CLIENT_TOKEN 为用户随机生成的连接 Token；PUBLIC_BASE_URL 为部署后的固定 HTTPS Worker origin；BOT_NAME 为展示名称。Webhook 与签名 secret 留在 Worker，插件仅保存 origin 和 CLIENT_TOKEN。查询配置接口只回传 provider、protocolVersion、botName 和能力，不回传 secret。

## 接口契约

| 接口 | 认证 | 行为 |
| --- | --- | --- |
| GET /v1/health | Bearer CLIENT_TOKEN | 返回协议版本 1、provider grok-bot、botName，不触发生成 |
| POST /v1/jobs | Bearer CLIENT_TOKEN | 接收稳定 jobId 与 prompt，首次触发，重复请求返回原状态 |
| GET /v1/jobs/:id | Bearer CLIENT_TOKEN | 返回 jobId、status、result、updatedAt、reasonCode，不回传回调密钥 |
| POST /v1/callback | 本任务 token | 幂等保存生成结果 |

状态：dispatching、accepted、unknown、completed、failed。202 仅说明接受。未知状态不得等同未执行。绑定测试先查健康和认证，再由用户明确点击生成测试；测试结果回传成功才标为实测可用。重绑失败保留旧连接，解绑不删除云端历史。自定义域名按用户手势请求精确 HTTPS origin 权限。
