# AI 生成引擎与就地 Bot 选择

## 需求与交互

将生成通道和自动生成内容合为“AI 生成”单选框：关闭、X Grok、Grok Bot、Grok Webhook。新配置默认引擎 X Grok；保留已有开关及通道，不自动启用生成。引擎选择随保存配置生效，连接配置仍单独保存。

Grok Bot 在当前创作模块显示实际 Bot 下拉框，通过读取本地服务 Bot 列表确认连接，不发送生成请求。未连接时展示配置入口；完成配置后可重新检测。Webhook 放在末位并标明备用用途。系统设置中的测试 Bot 仅用于连接测试，同一端口与 Token 下不会改变已选的生成 Bot；更换连接时重新验证并采用测试成功的 Bot，创作模块可再选。

现有连接配置界面和服务继续复用，不新增连接框架。标签与选择框使用 flex 居中和 10px 间距，提示支持焦点阅读。

## 实现边界

- 公共 generation-choice 模块统一引擎目录、状态检测、就地 Bot 选择与保存。
- 为兼容已有配置，内部 grok 对应 X Grok，grok-local 对应 Grok Bot，grok-bot 对应 Grok Webhook；不重写旧任务的连接快照。
- Grok Local 增加 selectBot，只读取列表验证并保存选择，不消耗生成额度。系统连接测试增加 preserveBot，避免诊断操作切换同一连接的生成 Bot。
- 保存前验证 Bot 可用性及引擎连接；后台明确拒绝保存时恢复原引擎及 Bot。请求异常可能已经保存，故不在响应丢失时自动回滚或重发。
- 引擎和 Bot 为本机共用，自动生成开关和发帖配置仍按队列账号保存；tips 明示范围。
- 不接入尚未实现的 Codex Bot，不改变自动公开发布开关。
