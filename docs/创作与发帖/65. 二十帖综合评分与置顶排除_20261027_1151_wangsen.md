# 二十帖综合评分与置顶排除

创建时间：2026-10-27 11:51；作者：wangsen；首轮候选版本：3.3.3；后续完整实机验收修正版：3.3.4。

## 需求与最终规则

用户指出互关刷评会使低质量帖的评论数很高，要求将候选范围扩大到 20 条，评论、转发、点赞、收藏权重固定为 1:3:3:3；同时绕开长期置顶帖，并明确仍按原概率决定是否评论。这一轮替代前一轮单看评论数的方案。

1. 先排除明确标记为置顶的帖子，再取最近最多 20 条普通时间线帖子。置顶帖不占 20 条名额；第一条若为普通帖则保留。
2. 现有原创、链接、去重、范围门禁和历史评价去重继续生效。
3. 综合分＝评论数×1＋转发数×3＋点赞数×3＋收藏数×3。系数占比分别为 10%、30%、30%、30%；使用原始数量加权相加，不按单维度最大值归一化，不加浏览量或额外惩罚。
4. 程序选综合分最高的一条，同分保留时间线靠前的一条。互动分只是排序指标，不能证明内容质量，也不识别或保证消除刷量。
5. 原参与概率、单次抽样结果及不重抽机制保留。未抽中不调用 Grok；0% 暂停自动创作；高分不绕过概率。
6. 抽中后只把唯一原帖交给 Grok 评估内容质量并写作；仍可因质量不足跳过，但不换帖。正文补全、生成重试沿用同一来源，已有草稿与发布结果不明的处理规则保留。

## 指标读取与复用

继续复用现有主页读取、profile-access、队列及 Grok 写作模块。复查 [Lodash 开源项目](https://github.com/lodash/lodash) 与 [X 官方数据字典](https://docs.x.com/x-api/fundamentals/data-dictionary)，本次只有固定四项加权与最多 20 条最大值比较，原生数组已满足，无需引入统计库或重新实现通用框架。

- `src/platform/x/page-reader.js`：在截取数量前排除置顶标签；读取评论、转发、点赞与公开显示的收藏数。空收藏图标不证明零收藏，保留未知。
- `readPostMetricsOnPage`：在 MAIN world 只读当前已加载的 React 帖子数据，逐项匹配目标帖子 ID，取 `reply_count`、`retweet_count`、`favorite_count`、`bookmark_count`。不发网络请求、不调用组件方法、不点击控件；数据结构变化时保留未知值。
- `src/platform/x/profile-access.js`：统一在 DOM 读取后按帖子 ID 合并有效计数；没有匹配或读取失败时保留 DOM 结果，不能借用引用卡片或其他帖子的数字。
- `src/features/grok/grok-comment.js`：`postEngagementScore` 实现固定公式，`highestScoredPost` 在非置顶的前 20 条里选最大值。多条候选有未知、负数等无效指标时不冒充完整排名，跳过并说明；只有一条候选不需要跨帖比较。
- 队列在浏览过程中累计普通帖，最多 20 条；读取不足时使用实际已读范围，不能声称已读满 20 条。连续两轮没有新增或达到 20 轮停止，保留现有任务时间预算。
- 评论、引用、文章及旧版独立新帖共用这一选择入口；面板 tips 和 README 同步最终规则。
