# Grok Bot 本地通道与任务恢复

## 需求与体验

在创作设置增加独立的 Grok Bot 选项。首次选择未验证连接时打开系统设置，填写端口和 Token、读取并选择具体 Bot，生成测试成功后保存和启用。重新打开设置自动还原端口、密码框中的 Token 和所选 Bot 名称。更换端口或 Token 清除旧 Bot 列表，避免使用其他连接的候选；测试完成时不清空已保存的表单。

Token 仅保存在本机专用 Dexie 数据库，不进入业务备份。状态查询和任务检查点不携带 Token。服务检查 Host、Bearer Token 和精确的扩展来源。403 提示改为直接说明添加扩展地址并重启服务；配置完成后收起连接步骤。

## 会话与接口兼容

2026-10-28 原服务曾返回 `listAgents failed: 417 Expectation Failed`；随后桌面端移除缓存路由，CLI 0.12.4 误报缺少本地 agents 目录。用户重启桌面端后，原 CLI 会话和 Bot 列表恢复。

本地服务 0.2.1 复用上游 PR 145 固定提交 `9c36b08cee62186eb23279b4d8e435ca1dfd0da2` 的兼容 CLI，附 MIT 许可、来源及文件校验值。仅补充获取新路由和调用方 clientNonce 两处适配，不自行实现凭据解密。Windows 自动读取实际桌面端版本，使用当前活动账号和其团队，不修改桌面凭据。EXE 内置 CLI，仍需要 Node.js 22.19+。

真实网关可能已收到消息却不返回 messageId。发送前持久化唯一 clientNonce，随后通过用户消息的同一 nonce 取得 requestId，只接收对应回复；不能仅靠文本相同或历史消息推断结果。

## 中断与恢复

扩展发送前先保留任务编号；服务持久化任务后异步发送，扩展使用短请求查询。服务重启后，有消息 ID 或 nonce 的任务只恢复查询，不再次发送。发送过程不明或无法关联结果时保留待确认，不自动重发。相同任务编号与内容幂等，不同内容返回 409。

服务的 config.json、jobs 和 .gbot-runtime 保持本机私有；公开发行只包含源码、EXE 和校验文件。下载与使用说明见 [0.2.1 发行页](https://github.com/wangsen2020/gbot-local-service/releases/tag/v0.2.1)。

- 服务模拟检查 34 项通过，覆盖无 messageId 的 nonce 关联、重启恢复、幂等冲突、EXE 内置 CLI 与许可校验。
- 真实服务发送后重启测试服务，从原任务取回“中断后回复可找回。”。
- 在现有 CDP Chrome 中加载测试扩展，8787 端口选“互粉”完成真实测试；关闭并重开设置，端口、Token 和 Bot 名称仍被还原。
- 停止测试扩展 Service Worker 后，在全新的后台上下文调用原任务续查，取回“后台恢复成功。”，没有重新发送。
- 生成通道实际包含 Grok、Grok Hook、Grok Bot 三项，选择后保存为 grok-local。
- 用户确认测试评论及发布正常，并明确要求直接集成后统一测试。本轮没有额外发布 X 测试内容。

## 集成与运行

功能基于 3.7.4 开始，集成时以最新 develop 3.7.5 为准，保留 3.7.5 的源码换行、教程校验及发行说明。使用标准 Git Flow feature finish 完成本次特性合并；主扩展构建加载 3.8.0 开发版。扩展商店及正式 3.8.0 发行不在本次范围。
