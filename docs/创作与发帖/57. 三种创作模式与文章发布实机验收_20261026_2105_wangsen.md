## 交付范围

发帖形式提供评论、引用评论、文章三种单选，默认引用评论。各自使用独立提示词与发布实现，沿用统一创作概率、一次抽样、账号核验、内容风险与发布前设置检查。既有 original 普通新帖任务继续按原定形式处理；旧设置仍为 original 时界面提示用户明确选择新形式，不将旧任务静默转成公开文章。

文章包含 title、Markdown body、description、coverPrompt 及至少一张 5:2 封面。正文生成要求有信息量的小标题、短段落、适量列表与重点加粗，保持事实归因和固定奖励不等于复利的边界。复用用户提供的 MIT 项目 x-article-exporter 的 Markdown 转换器，保留许可信息。

文章元数据、封面和配图请求检查点随评价存储，配图失败保留正文并停止自动重复请求。Cloudflare 接入是独立能力，本轮文章实发使用此前已经生成的 FLUX 图片，不将其记为 Cloudflare 或 Grok 生图成功。

## 发现和修复

1. 正文保存存在防抖延迟。旧的保存提示仍可见，不能证明新正文已上传。写入后等待，另开任务窗口从列表进入精确草稿 ID，再核对完整正文与封面，避免刷新打断保存。
2. blob 裁切预览曾被当成封面上传成功。现在过滤临时 URL，等待实际应用裁切和服务器图片加载。实测发布封面原图 1280×512，展示图 1200×480。
3. 直接打开编辑链接可能出现分栏空白。从草稿列表中只点击任务创建的精确 ID，不使用第一条草稿。
4. 发布弹窗外层 role=dialog 可没有尺寸，不能据此认定不可见。以弹窗内可见说明输入框识别，正确填写短描述再点击最终发布。
5. 旧的逐段 DOM 写入产生过重复、乱序；改为一次 Markdown → HTML 富文本粘贴，核对 Draft 最新内容状态和重新打开后的实际内容。

首次生成描述达到294加权字符，被校验拦截。增加一次有明确纠错原因的生成重试，并拒绝正文完整照抄素材长段落。提示词末尾补充独立分析、短段落与固定奖励不等于复利的自检。后续人工阅读仍发现复利错误，再次调用 Grok 后正确说明固定基数下的线性奖励；将新生成正文更新到同一任务草稿，复用已生成封面。不能将此过程描述为一次无人干预全链成功，也不能把这条提示词当作通用事实准确性保证。

草稿重新打开一度停留在加载状态；经 CDP 恢复渲染确认完整内容已保存。修正临时动画帧兜底：遮挡窗口即便报告 hidden=false 也使用定时器与原生帧竞速，只执行一次；保存复核窗口在加载完成前也尽早注入。使用新开的非聚焦窗口重新验证同一草稿，未启用 CDP 焦点模拟，即取得完整正文、标题及1020×408封面一致的结果。

### 3.2.3 配图来源纠正

按用户要求，文章始终优先调用 X.com Grok，绑定 Cloudflare 不再切换主服务。Grok额度不足、出图失败或超时时，才调用已绑定的Cloudflare一次；账号不匹配、任务取消或权限条件变化时停止，不通过兜底绕过检查。封面保留实际provider，以及fallbackFrom、fallbackReason供排障。

Grok绘图请求加入文章标题与短标题排版要求，覆盖旧草稿提示词中的无文字要求，文字和主体放在5:2中央安全区域。Cloudflare仍生成无文字备用封面；设置入口tips与绑定弹窗说明同步。1040项测试及54项构建测试通过，已加载3.2.3；本轮未重新消耗生图额度，含文字海报的实际视觉质量尚待下一次生成核验。
