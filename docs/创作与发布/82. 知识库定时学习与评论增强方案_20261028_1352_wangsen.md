## 1. 最终产品模型

经验是每日分析积累的素材；智慧是一份Markdown写作Skill，整理如何写好帖子、如何引发有价值互动的经验。内容围绕选题、信息价值、表达方式、互动问题、适用条件和避坑，不承诺流量，也不鼓励编造事实或空泛互动诱饵。

每个X账号可以保存多份智慧，但只勾选一份作为当前使用的Skill。选择方式类似默认地址：切换仅改变使用项，不改内容、不新增版本、不称作回退。

只有手动编辑保存、手动经验合入、每周自动合并产出才新增一份文档。即使当前选中旧版本，新文档也沿全部历史的最大编号递增，不复用旧编号。原文档一直保留。

用户已明确选择：每周合并自动保存新的智慧并设为使用；之后可以随时勾选其他智慧。

## 2. 页面与弹窗

### 主页面

- 顶部操作区只有一个大脑图标；hover显示当前使用的版本，点击打开智慧Markdown弹窗。主页面不再展示智慧正文或大型智慧卡片。
- 显示两行紧凑执行概况：每日总结、每周合并的计划时间、最近结果与产出；提供立即总结、立即合并、执行记录。
- 主要空间留给经验列表。列为勾选、摘要、来源、状态、总结时间和眼睛详情图标；全文、条件与单条操作在统一详情抽屉中查看。
- 经验分页保留20、50、100条；分类为待合入、已合入、全部、已忽略。当前使用项变化后，已合入状态随其经验快照变化。
- 来源select仅显示“全部来源”等选项，不再在前面重复添加“来源”标签；语义由select本身及aria标签表达。
- 控件、行列和模块之间由单一布局容器负责10px间距，内容与表格单元格padding为10px，避免margin与gap叠加。

### 智慧Markdown弹窗

采用与执行日志相同尺度的居中弹窗，桌面宽度840px以内、窄屏94vw以内、高度最多85vh。原生dialog负责焦点和Esc关闭。

显示当前查看的版本与当前使用项，正文为可编辑Markdown。支持复制Markdown，也可将其他AI细化的文档粘贴回来。点击“保存并使用”新增文档并选中，原文档保留。

编辑期间后台刷新不覆盖输入；若当前使用项已变化，保存时拒绝覆盖并保留文本供用户复制。当前文档上限6000字符，超出时服务端明确拒绝，不静默截断输入。

### 智慧版本弹窗

点击“版本记录”打开居中弹窗。默认每页10条，可切换20或50；列表显示使用单选框、版本、保存时间、来源和查看图标。

勾选立即设为当前Skill，版本总数不变。点击查看图标打开该份Markdown；从旧文档编辑保存时，保留其来源经验快照，并沿最新编号新增。

只向列表返回当前页元数据；查看全文和选择使用项均按账号及版本精确读取，避免将所有历史正文一次加载到弹窗。

### 执行记录弹窗

“执行记录”打开居中分页弹窗，默认10条，可切换20、50，支持全部、每日总结、每周合并过滤。每行显示时间、任务、状态、产出和详情。

点击详情查看本次材料数量、剩余待合入数量、分阶段时间线及异常原因。包括准备材料、提交、保存原任务编号、接收完整结果、校验、经验入库或智慧保存。

历史采用数据库时间索引查询；页面按需返回本页记录，不使用无限滚动。

## 3. 经验与来源

| 渠道 | 记录内容 | 状态 |
| --- | --- | --- |
| 低质帖分析 | 本账号样本、原帖、分析批次及时间 | 已接入 |
| 优质帖分析 | 本账号优质样本、原帖、分析批次及时间 | 已接入 |
| 榜单优质帖分析 | 来源作者、完成的榜单样本及帖子 | 已接入本地材料 |
| 博主帖子总结 | 将来记录指定博主的身份与来源 | 未接入，选项禁用并明示 |
| 手动录入 | 人工经验，可附来源链接 | 已支持 |
| 历史来源待核实 | 缺少明确渠道的旧记录 | 保留且不编造分类 |

来源保存账号、经验ID、渠道、原帖ID、作者ID、采集时账号名、URL、分析任务、采集时间与总结时间。来源由程序从冻结样本生成，不交给模型编造。

相同经验再次被支持时追加来源；低质和优质分析可以同时支持同一经验。来源和经验都成功保存后才登记增量进度。

低表现只表示待复盘，不直接证明内容差；高曝光不直接证明内容好。外部样本仅形成有条件的观察。

## 4. 每日总结与每周合并

默认两个自动开关均关闭，保留原有行为。开启后，Chrome alarms每15分钟检查到期任务；浏览器关闭时暂停，恢复后合并检查，不为漏过的每个时点补发请求。

每日默认09:00检查。只使用已有本地成熟样本，每批最多6条同来源、同用途材料；自己的帖子至少24小时且满足当前成熟时间，使用90天内样本；外部来自近30天完成的榜单。相同材料不重复分析，指标变化后的同帖至少间隔7天再纳入。

没有新材料时记录“已跳过/无新增材料”，不调用AI。正常记录新增、复用经验数量及完整执行过程。

每周默认周日22:00开始合并。取待合入经验，结合当前Skill融合为新Markdown，自动保存并选为使用。每批最多10条；积压未处理完时15分钟后接续下一批，每批形成一份智慧。每日预算默认2次，可配1至5次；预算用完次日继续，先执行到期的每日总结，避免周合并挤占每日分析。

合并只重写智慧，不删除经验或证据。若出现明确冲突、基线变化或来源经验修订，则保留当前使用项，标记待处理；用户可以查看结果、放弃并重新合入。

## 5. 智慧Skill与生成增强

融合提示词要求输出结构化Markdown写作Skill，建议2400字符以内，保留有效原则、适用条件和例外。压缩不能保证完全无损，因此每份文档保留来源经验快照与全文，支持查看和选择。

关注队列AI生成中的“知识增强”仍默认关闭。开启且本地通道、固定Bot一致时，使用当前勾选的Skill全文和版本；不再从零散经验临时选取5条。存在智慧时不额外叠加旧写作记忆；没有智慧时沿用原流程。

文档保存、选择不会触发AI。生成请求与Skill、原帖合计仍受本地服务8000字符限制，超出时保留文档并返回现有通道的明确长度错误，不截断内容。文章与原创模式的自动接入仍不在当前范围内。

## 6. 数据与恢复

复用项目已有Dexie、Chrome alarms、knowledge-queue和Vue组件，不引入另一套CRUD或调度框架。

调度库从v1至v3依次增加来源、智慧文档、使用指针、合入任务及时间索引；升级保留既有设置、记录和文档。当前使用指针以账号为键，文档以账号和递增编号为联合键。

新文档保存与使用指针在事务内提交；单选切换在事务内更新指针，不新增文档。经验总结和智慧生成通过统一事务领取预算，避免并发超额。

发送前先登记状态，再保存原任务编号。中断后只查询原任务；完整结果先保存后解析。记录阶段变化与时间，不以收到HTTP响应替代生成完成。自动周合并不会重复发送已登记的请求。

编辑保存验证打开时的当前版本，合入还校验所选经验版本。账号切换、未知结果或冲突不覆盖其他账号和新决定。

官方依据：[Dexie](https://github.com/dexie/Dexie.js)、[事务与升级](https://dexie.org/docs/Tutorial/Design)、[Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)。

## 10. 统一帮助样式与间距验收

按用户再次明确的UI规范，将本轮新增问号全部改为复用InfoTip组件。组件统一14×14实心圆、白色问号、零边框；周围间距由容器统一负责，不追加3px或其他隐式margin。

分页中的“每页”、select和“条”分为明确的子元素，使用10px gap；浏览器按实际边界测量文字到select为10px，而不是只检查CSS声明。

原生dialog属于浏览器顶层，共用InfoTipLayer现在将提示挂到当前dialog内，避免body层提示被遮挡；继续使用原有定位算法处理窗口边缘。真实浏览器确认帮助文字位于当前弹窗、实心背景为rgb-118-146-135、文字为白色，390px下提示完整且不越界。
