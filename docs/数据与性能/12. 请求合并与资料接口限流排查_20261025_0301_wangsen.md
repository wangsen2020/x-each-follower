# 12. 请求合并与资料接口限流排查

- 创建时间：2026-10-25 03:01，作者：wangsen。
- 涉及版本：2.12.5—2.12.7；分支：feature/recent-feature-tutorials。
- 按用户要求独立归档，从第 4 篇移出本次请求合并及限流排查记录。本文记录已完成工作及证据边界，不代表发行公告。

## 1. 问题与结论

用户反馈自动队列频繁提示“用户资料接口限流，未发送关注请求”，但手动访问和关注正常；另有同一日志同时显示“关注成功”和限流原因。

排查区分了两个问题：成功日志继承旧失败原因，是确定的记录错误；资料查询 HTTP 429 则来自独立的读取接口，不能因为关注成功就判定它是误报。队列打开主页后额外查询资料、多个调用方并发重复读取，会增加资料接口请求量。本次减少可证明重复的请求，没有绕过真实限流或取消必要核验。

## 2. 排查证据与局限

### 2.1 成功记录残留旧失败原因

@alphavishall 的 2026-10-25 02:16:40 记录为资料读取限流；02:33:20 后续记录为关注成功，但合并结果时保留旧 followResult.reason，界面将其展示在成功记录中。只读查看真实主页，按钮显示正在关注。2.12.5 清理成功结果中的旧失败状态，并修正历史成功日志的显示，原始历史失败记录仍保留。

### 2.2 资料接口与关注接口分别判断

X_PROFILE_READ_LIMIT 仅在资料查询返回 HTTP 429 时生成，普通超时另用 X_PROFILE_READ_TIMEOUT。资料查询使用 UserByScreenName，发送关注使用独立的写入接口；手动关注成功不能证明资料查询当时没有被限流。

历史诊断没有保存原始响应和限额头，无法逐条还原 02:16 那次服务器配额。确认的是代码进入了 HTTP 429 分支，不能据此补写不存在的历史响应证据。

### 2.3 实际网络观察

独立测试标签页打开 @alphavishall 时，页面原生查询与扩展额外查询使用同一个 UserByScreenName 路径。该次均返回 HTTP 200，服务器报告限额 150，观察到剩余次数 50、48；后续验收同一重置窗口观察到剩余 11。期间其他后台任务也在运行，不能把额度减少全部归因于测试或关注队列，也不能把一次观察推广为所有账号的固定限额。

2.12.6 开始保留资料读取限流的 HTTP 状态、operation、rateLimit.limit、rateLimit.remaining、rateLimit.resetAt、retryAfterSeconds 和 observedAt。没有服务器字段时保持缺失，不推算平台保证恢复的时间。

## 3. 全局调用链盘点与处理

| 路径 | 发现及处理 |
| --- | --- |
| 关注队列主页与身份核验 | 复用同页、同目标、30 秒内的原生成功资料响应；网络兜底结果继续复用到身份核验 |
| 榜单资料、面板资料刷新、粉丝和关注列表扫描 | 接入原生资料响应复用；仅允许主页及受支持的资料子路由 |
| 同页并发资料、列表、帖子及分析查询 | 统一网络入口按请求路径、参数和会话请求头合并进行中的相同 GET；完成后立即移除，不缓存完成结果 |
| 分页 | 不同游标及变量保持独立，既有空页与游标不前进停止条件保留 |
| 关注、取关、拉黑、删除等写入 | 不合并；写入开始和结束清除当前页读取合并表及原生资料快照，后续核验不复用之前的在途读取 |
| 自动取关、问候收件人核验、关注结果复核 | 保留实时资料读取，避免过期关系影响实际操作；并发相同读取仍由统一入口合并 |
| 跨标签页和不同登录会话 | 不合并，没有足够的统一身份与操作顺序信息，不能安全共享关系结果 |
| Grok 生成和发布 | 保留独立任务及既有防重逻辑，不按普通 GET 合并，避免不同任务共享生成结果 |

## 4. 合并规则与安全边界

### 4.1 原生页面响应复用

只复用当前页面、当前目标、30 秒内的成功资料响应；路由限定为主页或受支持的 followers、following、verified_followers、with_replies 子页。返回数据仍须经过调用方目标 ID、账号名与关系检查，不凭历史粉丝来源放行。关注结果复核等默认请求不启用这项复用。

### 4.2 合并进行中的相同读取

统一网络入口只合并同一页面中的 GET 查询，键包含来源、操作、完整路径及查询参数、会话请求头。不同游标、目标和会话头各自执行。请求完成或失败后立即移除，不将完成结果作为通用缓存。每个调用者得到独立结果副本，避免互相修改数据；旧请求结束时仅删除自己对应的条目，不误删后来的同键请求。

### 4.3 写入隔离

关注、取关、拉黑、删除等写入不合并。写入开始和结束都清除当前页面的在途读取合并表及原生资料快照，使后续核验不会加入写入前的读取。跨标签页不共享结果，也不宣称实现跨标签页的统一缓存失效。Grok 生成和发布继续使用独立任务及既有防重机制。
