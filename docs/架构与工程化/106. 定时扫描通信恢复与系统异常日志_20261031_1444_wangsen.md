## 错误证据与修复

Chrome 保存的错误来自三个 `panel.html?scheduledFollowers=...` 上下文，两次明确在自动入队请求上记录 `Receiving end does not exist`，同时有异步响应通道提前关闭。当前后台仍能回复 4.11.5 版本握手，不能据此解释历史故障的具体触发时间与原因。

- `requestBackground` 复用已有 p-retry，仅对 Chrome 明确未建立接收通道的错误，首次请求外最多重试两次。响应通道关闭或扩展上下文失效时不自动重放写入，以免将“已完成但回执丢失”执行两次。
- 定时扫描监听器在目标面板不匹配或标签查询失败时返回明确回复；扫描失败单独记录，其他消息不声明异步回复。
- 定时完成消息先响应，再异步关闭经 URL、token、sender 校验的单个定时面板。
- 补齐后台网络模板读取、评论执行的异步拒绝回复。
- 自动入队反馈分为关闭、无候选、已确认、失败及结果待确认，不再把 count 为零或请求失败显示为“已在队列”。确认数量来自后台回执，日志账号来自后台返回的任务。
- 系统日志记录后台返回的错误，避免只存在于调用页面的瞬时提示里。

参考 Chrome 官方消息约定：[Message passing](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)。评估过 [webextension-polyfill](https://github.com/mozilla/webextension-polyfill)，其 API 兼容层不能替代缺失的业务响应、修复关闭顺序或判断写入结果，本轮继续使用原生 Chrome API；重试复用项目已有 p-retry，数据 CRUD 与事务复用已选定的 Dexie。

## 系统设置中的异常日志

入口：左下角系统设置 → 异常日志。独立于各业务执行日志，不修改已有操作历史与业务备份。

记录扩展后台和面板的未处理异常、Promise 拒绝、Vue 错误、控制台 error/warn、后台请求错误，以及 X 内容脚本中属于本扩展的异常。不会拦截普通 X 页面脚本错误。每条包含时间、来源、级别、类型、版本、页面和堆栈。

日志使用独立 Dexie 数据库 `xfollower-system-exceptions`，保留近 7 天、最多 1,000 条。后台和面板可直接写同源数据库，不依赖后台消息存活。数据库写失败或内容脚本消息失联时，用独立 `xfSystemException:<id>` 键暂存于 chrome.storage.local，最多保留 100 条；启动或查看日志时回放并删除待写项。回放使用固定事件 ID，避免重复导入。

不存任意 console 对象、请求正文或消息 payload。入库前裁剪长度，过滤 Bearer、token、API key、密码、cookie、JWT、外链查询参数和 webhook 路径。复制与导出仅包含当前筛选结果；用户仍应检查准备对外分享的日志，脱敏规则不保证识别任意未标识的机密文本。

界面支持来源、级别、全文搜索、30 条分页、展开堆栈、复制、JSON 导出、确认清空、读取失败与重试。按本轮验收反馈，重复的来源与级别标题已去掉，分页移至筛选右侧，保留规则说明收进悬停或键盘焦点提示。直接读取数据库，因此后台失联时设置页仍能打开异常记录。普通可恢复状态仅保留本机日志，不新增桌面通知。

这是从本版本开始的运行日志，无法追溯导入 Chrome 扩展页已保存的旧错误；语法错误、脚本尚未加载时的启动失败、被业务主动吞掉且未报告的异常以及 Chrome 自身错误不属于自动捕获保证范围。

## 本轮实机发现的两个补充缺陷

1. 设置弹窗采用 transform 居中，原生提示层却沿用窗口坐标，造成位移叠加和右侧裁切。提示层在原生 dialog 内改用绝对定位和弹窗局部坐标，并在弹窗可见范围内避让；DOMRect 属性位于原型上，必须显式读取 width，不能用对象展开取代。原来的页面级 fixed 定位保持原行为。
2. JSON 导出的 Blob 地址在 1 秒后释放，当前 Chrome 尚未完成保存，导致下载先接收到全部字节后取消。实机延迟释放后能够保存，最终调整为 40 秒，并将提示改成“已开始下载”，不凭发起下载就声称落盘成功。评估了 [FileSaver.js 原生下载分支](https://github.com/eligrey/FileSaver.js/blob/master/src/FileSaver.js)，其同样延后 40 秒释放；本轮是现有 Chrome 原生导出的生命周期修复，无需引入旧浏览器兼容层。
