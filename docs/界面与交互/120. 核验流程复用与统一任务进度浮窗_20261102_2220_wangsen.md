# 核验流程复用与统一任务进度浮窗

创建时间：2026-11-02 22:20。开发分支：feature/fan-review-flow。

## 需求

关注队列与粉丝管理的待核实共用交互与流程：启动时固定选择，执行期间维持勾选但不可再次选择；切换分类、搜索、分页或其他模块不结束任务。进度、显式停止与继续统一放入浮窗，结束结果持续保留，由用户手动关闭。

此前关注队列使用顶部三秒消失提示，粉丝管理分别使用页内及全局进度栏，生命周期和选择限制不一致。重新进入关注队列还会销毁前端控制器，使未完成的请求失去原任务上下文。

## 实施边界

- 复用现有 Vue Sonner 和 ResultNoticeCard，不新增通知或通用队列库。GitHub 官方 p-queue 提供并发排队能力，但不承担本项目已实现的账号归属、检查点和落库规则，故保留领域适配层。
- verification-workflow.js 共享顺序执行、错误分类、安全暂停、停止边界、游标推进和冻结选择；粉丝核验保留后台持久检查点，关注队列保留其请求与更新入口。共享执行流程不改变两处的业务写入目标。
- createTaskProgressReporter 按稳定任务 ID 原位更新卡片，保留初始时间；完成或失败后没有自动关闭倒计时，关闭后的同一结果不会被轮询重新弹出。
- ResultNoticeCard 共用进度条、处理数、成功与失败数，以及图标形式的停止、继续和关闭。操作保留本地化名称、悬停与键盘焦点提示。
- 粉丝管理锁定正在启动或运行的批次；后台审核状态额外返回最小固定 handles 列表，用于恢复勾选，不返回完整资料。
- 关注队列允许运行期间切换视图；同一绑定账号重新进入模块时复用原控制器，恢复仍从原游标继续。不同绑定账号不继承原任务。

关注队列的批量核验仍是当前面板持有的任务，切换模块会保留，关闭或重载整个面板不等于后台持久恢复；粉丝核验的后台检查点行为保持不变。不得把两者的不同持久化能力描述为相同。
