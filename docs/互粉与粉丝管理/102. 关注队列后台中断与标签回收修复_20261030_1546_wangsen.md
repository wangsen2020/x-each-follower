## 原因与证据边界

执行函数每次新建标签，仅依赖当前执行的 finally 清理。后台上下文中断后，恢复逻辑只恢复任务状态，没有接管旧标签；安全的前置任务又立即恢复待处理，形成重复创建。

租约心跳仅访问 IndexedDB，不调用扩展 API；候选同步阶段没有独立的活动维持。Chrome 官方说明扩展 API 调用重置后台空闲计时器，普通定时器与 IndexedDB 不具备相同作用。该缺口与后台频繁重建的现场相符，但没有 Chrome 进程退出原因记录，不能排除重载、崩溃等其他来源。恢复设计必须容忍这些中断。

参考：https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle

已评估 @webext-core/job-scheduler：它封装 alarms 调度，项目已有该能力，不能代替任务标签归属、租约和副作用恢复。继续使用现有存储与调度能力，仅补业务适配，没有引入新的通用调度框架。

## 修复

- 仅在关注批次运行期间每 20 秒调用 runtime.getPlatformInfo，覆盖候选同步、执行及结果同步；结束后清除计时器。
- 将任务标签 ID 与预期 URL 登记到 storage.session，跨 worker 重启保留，避免跨浏览器会话误用旧 tab ID。新批次先回收登记项。关闭失败保留登记，下次创建同任务标签前先清理；用户导航到其他 URL 的标签放弃归属并保留。
- 任务 AbortSignal 触发时直接回收标签，避免网络请求未返回时 finally 永远等不到。正常 finally 幂等清理，清理异常记入审计，不覆盖已确认业务结果。
- 中断次数和下次执行时间持久化：第一次延迟 1 分钟，第二次延迟 2 分钟，第三次转待核实，停止该任务自动执行。后台重启恢复与租约过期恢复共用规则，来源重采集不会重置退避。显式重新放行任务时重置次数。
- 已尝试关注、移除或发布但结果不明的任务仍转待核实，禁止自动重发。其他可执行账号继续处理。
