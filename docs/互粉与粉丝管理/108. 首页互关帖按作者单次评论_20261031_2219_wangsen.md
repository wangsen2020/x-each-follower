# 首页互关帖按作者单次评论

## 目标与产品行为

4.14.0 新增“首页跟评 → 设置 → 互关勿评”，默认关闭。开启后，当前账号已经成功评论过的作者，其后续已确认互关帖不再进入 AI 评论生成和发布；其他作者继续处理。只依据成功评论记录，不能仅凭“已关注”跳过作者的首次评论。采集和 AI 打标仍沿用原流程，本开关节省重复评论生成的 token。

使用作者稳定 User ID 识别，按当前账号隔离；作者改名仍识别，其他账号占用相同 handle 不会被合并。缺少作者 ID、成功发布 ID、互关标签或成功状态时不猜测匹配。失败、草稿、待核实和发布中记录均不当作成功凭据。核实发布成功后同样登记。

跳过是随开关计算的视图：列表显示“已跳过”与原因，但数据库原标签、评论草稿、AI 回执和状态保留；关闭后未发布记录恢复原处理。切换期间在知识读取后、生成前、发布前及实际提交前复查最新设置，保留已付费生成的草稿。

## 方案与存储

已评估现有重复文本缓存：按作者、正文及引擎等信息匹配，7 天有效，不能表达长期按作者只评论一次。继续使用项目已集成的 Dexie 4.4.7，不引入新 CRUD 或迁移框架；业务只新增成功作者凭据及过滤条件。[Dexie 官方迁移说明](https://dexie.org/docs/Version/Version.stores%28%29)与[项目源代码及许可证](https://github.com/dexie/Dexie.js/)作为方案依据。

原 xef-mutual-comments-v1 数据库增加 Dexie version 3 的 commentedAuthors 表，主键为 ownerId 与 authorId，ownerId 索引用于当前账号列表过滤。升级从当前保留的已成功发布互关帖补录凭据；先前已被删除且没有可确认记录的历史无法凭空恢复。

成功状态及凭据在同一事务保存；自动清理 5000 条帖子时不删除作者凭据。账号配置增加 mutualCommentOnce，缺失的旧配置按 false 处理，保存时规范化为布尔值。开关关闭不删除历史凭据，后续重新开启继续生效。
