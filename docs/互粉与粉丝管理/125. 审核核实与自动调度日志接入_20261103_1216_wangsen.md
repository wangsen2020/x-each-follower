# 审核、核实与自动调度日志接入

## 范围

4.26.1 在粉丝管理现有日志窗口增加审核日志、核实日志、调度日志，保留扫描及队列回关入口。属于已有流程的日志补齐，不改变审核、移除、回关策略。

- 审核：记录持久任务阶段和各账号结论，区分审核通过、不通过、资料不足与技术异常；不通过同时显示移除执行状态。
- 核实：记录手动单账号、批量核实及自动补采，显示关系、等待原因、错误和重试时间。
- 调度：记录自动审核/核实执行或等待状态、本轮人数、处理人数及下次检查时间。相同空闲状态不按每分钟重复堆积，最长每 30 分钟记录一次。

日志仅保留必要账号、批次、状态及有限长度原因/标签，不记录 AI 提示词、原始画像、完整模型响应或连接凭据。旧版未记录的过程不补造；更新后的持久检查点变化开始产生记录。

## 实现与复用

复用 `execution-log-store` 已有 IndexedDB 索引、游标分页、备份与分类清理；新增 `fanReview`、`fanVerify`、`fanSchedule` 范围，查询/清理只作用于当前分类。无需新建数据库或引入日志框架。

审核及手动批次从 `chrome.storage.onChanged` 的已提交检查点生成增量记录，用稳定事件 ID 防止重复结果；自动核实和调度使用同一写入入口。异步日志备份和写入错误不阻塞业务任务。

实现前已检查现有依赖及 [Dexie 项目](https://github.com/dexie/Dexie.js)，本轮无需替换现有日志存储或增加通用基础设施。界面沿用 Vue 日志窗口、共享 Lucide 图标按钮及键盘 tips，并参考 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines)。
