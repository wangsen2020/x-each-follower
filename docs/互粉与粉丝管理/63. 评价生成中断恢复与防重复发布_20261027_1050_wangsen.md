# 评价生成中断恢复与防重复发布

创建时间：2026-10-27 10:50

开发分支：feature/evaluation-recovery；已将本轮小范围补丁集成到当前 feature/release-readme-workflow 工作区，保留其他界面与教程改动，未提交或推送。

## 问题与证据

真实队列中一条已关注任务的旧版新帖评价为空，保留 generationAttemptedAt、generation_uncertain、11 次尝试及 2 次 Grok 调用。点击“核对评价”仍返回“上次 Grok 请求结果待核实，未重复调用”。

原实现只有保存了正文才能核对主页发布结果；正文为空时，又因已有生成时间而禁止调用 Grok。生成与发布的不确定状态没有分开，因此人工核对无法结束这段流程。

## 恢复规则

1. 人工核对遇到明确的生成检查点、正文为空，且没有发布时间、发布 ID、发布链接、文章草稿链接或历史发布阶段记录时，判定只进入过生成阶段。保留历史快照，结束此次核对，转为“待生成”，提供“重新生成”。本次核对本身不访问 X、不调用 Grok、不发布。
2. 正文存在的待核实任务继续使用现有发布核验。已有发布尝试或阶段依据不足且缺正文时，不给予重新生成权限，提示从溯源详情核对历史，避免把未查到当成未发布。
3. 恢复任务持久化 recoveryDraftOnly。人工重新生成即使收到 publish=true 或账号开启自动发布，也先保存草稿；只有草稿已存在，用户另一次主动点击发布，才可进入发布流程。后台自动评论不会领取这些恢复任务。
4. 重新生成遇到提交前额度不足时，保持可手动重试的失败状态，而非进入后台不会领取、界面也无按钮的 pending。提交后额度结果不明仍按生成核对路径处理。
5. 发布前必须成功保存 publishedAttemptedAt 检查点，否则不调用发布器；后续含默认零值的更新不能擦掉已有发布检查点。已发布记录直接返回，禁止重复发布。

本次不批量重置历史待核实记录，也不改变关注结果或旧任务的发帖形式。运行时状态使用既有 failed/draft/uncertain/posted，新增业务原因和恢复证据，不引入数据库版本升级。

## 历史记录

- recoveryHistory 按原生成时间标识保留恢复前完整评价快照，包含原因、形式、素材、尝试次数、调用计数和检查点；后续空数组更新不会擦掉已保存历史，同一恢复检查点去重。
- 原 generationAttemptedAt、attempts 和 grokCalls 不因核对清零。重新生成会正常记录新的时间和次数，之前的值仍可在快照中核对。
- “溯源详情 → 恢复记录”展示原状态、原因、生成时间与次数；同时追加执行日志。任务列表在可恢复状态显示“待生成 / 重新生成”。
