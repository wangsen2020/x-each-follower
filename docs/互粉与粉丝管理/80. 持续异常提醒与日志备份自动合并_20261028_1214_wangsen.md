# 持续异常提醒与日志备份自动合并

- 时间：2026-10-28 12:14，Asia/Shanghai。
- 本地版本：3.10.0；正式发行仍为 3.7.5，未提交、推送或发行。
- 用户目标：阻断性故障持续可见，避免忽略数小时；冲突由程序自动取舍和合并，不要求用户选择两份备份。

## 现场根因

3.9.0 的执行日志本地备份头停在 8943，X 页面内已提交链到 8986。第 8944 页分别被分配给两条不同的粉丝检测和评论日志，内容冲突。02:51 起多轮取关在写开始日志时退出，读取时累计 55 次；最后一次成功为 02:45:49。异常发生在更新调度状态前，因此面板仍误显示等待执行。

序号由实例内存中的 journalHead 分配，缺少跨页面和 worker 的共享写入协调；启动快路径采用本地进度，不能发现已经提交的远端进度。日志已在 IndexedDB 提交后，备份错误继续抛给业务任务，进一步扩大了影响。

## 统一备份的自动选择规则

1. 以已经提交且页号连续、内容校验有效的链作为主线，先完整读取冲突涉及的尾部，校验完成前不修改数据。
2. 按记录 ID 合并：不同 ID 是不同历史事件，全部合入同一主链；相同 ID 优先明确的较高 revision，其次比较写入或更新时间，无法排序或相同证据时采用已提交版本。
3. 采用完整胜出版本，补齐必要身份信息；不把旧版本的失败原因、评价和详情拼到新成功结果上。删除与清理记录同样参与顺序处理。
4. 待写操作重新分配为主链之后的连续序号，保持本地事务原子性，合并完成后清空对应 outbox。最终只有一条连续备份链和每个记录 ID 的一个有效结果，不建立第二条备份分支。
5. 已提交历史页是这一条主链的历史，不覆盖其正文；其他有效事件追加合入这条主链。待备份 outbox 是临时写入意图，完成后消除，不能作为另一份长期有效备份。
6. 通过 Web Locks 协调同一扩展内的跨页面、worker 写入；每次写入刷新已提交进度和待写最高序号，避免继续复用过期序号。
7. 缺页或损坏时不伪造内容、不跳过缺口，保留明确异常并停止不可靠的合并。当前真实冲突的主链完整，自动选择无需人工干预。

方案复用浏览器原生 [Web Locks](https://www.w3.org/TR/web-locks/) 与现有 IndexedDB 日志库，没有新增通用锁或 CRUD 框架。

## 异常提醒与业务行为

- 在 PanelHeader 统一展示持续异常条，覆盖各业务页面；包含原因、影响、首次发现时间、待备份数和处理说明。
- 详情可收起，故障本身没有“忽略即解决”的关闭按钮；查看日志或点击桌面通知不会清除持久化异常。
- 故障首次发现发送桌面通知，设置 requireInteraction；同一错误在 30 分钟内不重复打扰，未解除时继续提醒。点击通知进入关联面板。
- 提醒状态和发送时间持久化，后台重启不丢失、不重复立即通知。系统拒绝桌面通知时，在详情中显示发送失败原因，面板提示仍保留。
- 备份逐页完成时更新积压数；只有确认 outbox 归零才解除备份异常，部分成功不能冒充恢复。
- 仅备份失败且本地日志已经提交时，append 返回已保存结果及 backup.ok=false，业务不因备份失败终止；本地日志不可用仍抛错并报告异常。
- “重试备份”只重试存储操作，不重新执行关注、取关或发布；可重置已耗尽的传输重试次数。序号冲突即使此前耗尽重试，也可自动进入合并。
- 自动取关的真实全局暂停会持续提示；执行时段外和正常每日额度等待不作为故障告警。

桌面通知使用已有 [Chrome notifications](https://developer.chrome.com/docs/extensions/how-to/ui/notifications) 接口。系统通知的实际驻留仍由操作系统管理，面板提示承担持续可见的保证。

- 针对备份、合并、提醒的测试覆盖：序号冲突自动合并、同 ID 版本取舍、显式版本优先、缺页保护、两个已启动写入者并发、传输重试耗尽后恢复、提醒去重和跨 worker 重建、30 分钟提醒、权限拒绝、部分恢复不消警。
