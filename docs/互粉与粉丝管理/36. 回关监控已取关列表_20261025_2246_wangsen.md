# 回关监控已取关列表

## 需求与原因

回关监控原有数据查询支持 unfollowed，但页面只列出未回关、已互关和全部，且本地筛选主动排除了已取关记录。重新比对只返回仍在关注的账号，也会让历史在当前页面消失。

## 实现

- 新增“已取关”分类、数量、搜索及现有分页；“全部”继续表示当前主动关注账号。
- 展示原关注时间和取关时间；历史时间缺失明确显示“取关时间未记录”。已取关行不提供再次取关和豁免按钮，禁用选择及批量取关。
- 期限条件只作用于未回关分类；切换分类清除选择，避免残留过滤条件或跨分类误操作。
- 本地重新比对保留已取关记录，且不把它们计入待确认数量。重新关注后按当前关系展示，不重复出现同一账号。
- 手动取关成功回写 following=false。对仅由其他模块派生的账号，手动保存和自动回写都会创建独立 tracker 记录，避免来源更新或移除后历史丢失。

## 复用与写入边界

复用已有 record-runtime、panel-pages、记录索引、分页与 batch 写入能力，无新增存储库或并行事务框架。自动回写先保存当前账号的独立历史，再串行更新该账号其他来源；所有写入仍走既有记录服务、操作标识与备份恢复路径。此处不是跨来源原子事务，异常保持原有待核实与恢复流程，不新增外部请求。历史仅记录已回写的关系；本次不从失败日志推断成功，也不伪造旧记录时间。

## 2026-10-25 23:25 筛选仍显示零的回归修复

修复为 tracker 全量加载分别遍历 all 与 unfollowed 的全部分页，再按 userKey 去重；只有两类读取全部成功才标记完整。其他模块保持原有读取方式。仍属于第 36 篇需求的纠错，保留 2.16.0，不通过版本变更触发运行中的扩展重载。
