# 自动私信移除固定冷却与随机调度修复

创建时间：2026-10-26 15:00 · 作者：wangsen · 版本：2.19.3

## 问题与引入位置

用户看到“上次未发送，仍在一小时冷却期”27人，要求取消本地额外冷却，按调度重新核验并依据X实际返回处理。

该规则来自 `auto-greeting.js`，不是X返回的期限。Git可追溯到提交 `3cee187`，提交时间为2026-10-25 13:21，包含两条拦截：读取 `autoGreetingRetry:账号:目标` 的未来时间，以及检查发送台账中 `not_sent.completedAt` 是否不足一小时。失败和异常分支又会写入下一小时的时间。旧调度是固定每5分钟的重复闹钟。

## 本轮实现

- 删除两条冷却读取判断及失败后的时间写入，旧重试时间不再生效。不删除历史台账或批量修改用户数据。
- 明确未发送的候选，下轮调度重新读取本地记录、实时核验关系，并在提交前再次核验；根据聊天页实际返回记录失败原因。
- 成功、可能已提交、历史已提醒仍禁止自动重复发送。这是持久化防重复保护，没有时间到期自动放行。
- 调度复用Chrome闹钟能力：每轮结束后生成一个随机4–6分钟的单次闹钟，替代固定5分钟循环。已有未来单次计划在无关设置保存时保持；旧重复闹钟在恢复时迁移，关闭功能则清除计划。
- 每轮最多处理5人、同进程禁止重入、异常停止本轮及提交前条件核验保持。日志改为“下轮调度重新核验，按实际返回处理”；设置说明同步显示实际随机范围与防重复规则。
- 没有引入新的调度依赖或自研通用框架，仅调整原有业务规则与Chrome闹钟参数。
