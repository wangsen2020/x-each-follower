# 基于本地回关率的粉丝量权重

- 创建时间：2026-10-25 11:55
- 版本：2.15.0
- 数据范围：当前账号本地回关监控与关注队列；分析和验收均未额外请求 X。

## 需求与边界

将已有回关结果按对方粉丝数换算成队列权重，让更可能互关的普通候选优先执行，高粉且历史回关率较低的候选延后。该权重只调整执行顺序，不直接过滤账号。已经关注我们的待回关用户固定为 100，继续优先于所有普通候选；粉丝数未知时保持中性权重 10。

本次复用项目已有 `parseCount`、IndexedDB 队列和权重索引。通用排名方案调研确认可将不同量纲先转换为有界特征再组合；当前只有一个粉丝量特征，直接使用可解释分段比引入新的排名框架更合适。

## 本地数据依据与时间校正

初版直接用当前粉丝数分档，峰值落在 4000 至 4999。用户指出账号在关注后仍会持续增长，因此当前规模会把真正有效的关注时点向后错位。补充分析把当前回关监控与不可变原始档案中的 `followedAt + followersText` 精确关联：1349 个明确关注时间的账号中，886 个找到同次关注的历史粉丝快照，覆盖 65.7%。这些账号从关注到当前的粉丝增长中位数为 497，75 分位为 1282；部分增长快的账号超过 2000。

按关注当时粉丝数重新统计后，稳定主峰前移到 2000 至 2999：

| 关注当时粉丝数 | 历史快照样本数 | 当前已回关 | 回关率 |
|---|---:|---:|---:|
| 500 以下 | 67 | 27 | 40.3% |
| 500 至 999 | 63 | 42 | 66.7% |
| 1000 至 1999 | 149 | 105 | 70.5% |
| 2000 至 2999 | 123 | 98 | 79.7% |
| 3000 至 3999 | 79 | 56 | 70.9% |
| 4000 至 4999 | 49 | 33 | 67.3% |
| 5000 至 5999 | 47 | 33 | 70.2% |
| 6000 至 6999 | 21 | 14 | 66.7% |
| 7000 至 7999 | 16 | 9 | 56.3% |

8000 至 9999 只有 21 个样本，不能据此制造局部反弹；权重以 2000 至 2999 为峰值，之后采用平滑递减。历史快照描述的是关注发生时可见的粉丝数，正好与新候选执行前的当前粉丝数处于同一时点。数据仍只说明当前本地样本中的关联，不能证明粉丝量本身造成不回关。

## 权重换算

| 候选类型或粉丝数 | 权重 |
|---|---:|
| 已关注我们的待回关用户 | 100 |
| 2000 至 2999 | 60 |
| 1000 至 1999、3000 至 3999 | 50 |
| 4000 至 4999 | 45 |
| 5000 至 5999 | 40 |
| 500 至 999、6000 至 6999 | 35 |
| 7000 至 7999 | 30 |
| 8000 至 9999 | 25 |
| 500 以下 | 20 |
| 1 万至 19999 | 15 |
| 粉丝数未知 | 10 |
| 2 万至 29999 | 8 |
| 3 万以上 | 3 |

同权重仍按入队时间先后执行。权重不改变风险过滤、账号不可用拦截、关注与评论隔离或待回关放行规则。

## 实现与迁移

- `follow-queue-priority.js` 统一计算粉丝数权重，粉丝来源优先级保持 100。
- `follow-queue-store.js` 的实际任务领取改为按状态和权重索引选择，界面排序与实际执行一致。
- 队列数据库升级为版本 7，升级时为 6225 条历史任务重新计算时间校正后的权重，不丢弃任务、来源、结果或设置。
- “账号 + 状态 + 权重”升降序索引避免筛选待关注时扫描大量已完成任务，降低分页游标失效概率。
