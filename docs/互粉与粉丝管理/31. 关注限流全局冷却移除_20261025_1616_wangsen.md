# 关注限流全局冷却移除

创建时间：2026-10-25 16:16。作者：wangsen。开发分支：`feature/recent-feature-tutorials`。

## 现场与根因

2026-10-25 15:45 至 16:05 的关注队列日志反复显示“关注操作处于限流冷却，暂停至 16:08:04”。CDP 读取的队列日志确认，每次定时唤醒都在领取任务前被 `follow-cooldown` 阻断；时间过去后，队列才重新运行。

统一队列此前在 `friendships/create` 返回 HTTP 429 后写入 `monitor.pausedUntil = now + 1 小时`。`canRun()` 在每轮开始前和每个任务的动作检查时读取同一字段，整条队列因此停止。此字段是本地估算，并非 X 返回的恢复时间。旧的互关、粉丝手动回关及评论关注入口也读写同一个字段，可能再次延长全局阻断。

## 调整

- 移除关注相关入口对 `monitor.pausedUntil` 的写入和拦截。存储中已有的旧字段不再阻断队列，无需清除历史数据。
- 统一队列若收到关注接口 HTTP 429，将本账号任务保持为 `uncertain`，记录接口状态和“关系待核实”；立即结束本轮批次，避免本轮继续发送关注请求。
- 下一轮仍按用户配置的正常调度运行，可领取其他任务。待核实任务不会被盲目重复关注。
- 旧的自动关注入口在本轮遇到限流时结束本轮，手动关注入口只报告本次失败；不再写一小时全局冷却。
- 保留账号绑定校验、运行开关、任务租约、单任务重试与不确定结果核验。

## 复用与边界

复用现有队列调度、异常处理、任务状态和 X 接口响应，不引入新的限流调度库。原有 Grok 额度、私信和其他与关注接口无关的冷却规则不在本次范围。
