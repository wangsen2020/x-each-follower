## 一、背景与整体路线图

围绕 X（Twitter）账号的**粉丝资产管理**与**高价值互粉拓展**，近期在同一会话内完成了从底层数据解码、增量位点检索、双向关系四维分类、互粉意向与推荐评估，到互粉追踪全选定额操作及定时拟人浏览自动关注的完整闭环：

1. **粉丝管理增量检索与未互关清理**：解决大粉号（如 2W+ 粉丝）无法全量轮询的问题，引入不定频定时检索与增量位点（`checkpointHandle`），并提供“未互关”标签页支持全选与批量取关。
2. **昵称/简介乱码自愈**：在 `scoring.js` 增加 `repairMojibake`，把被按 Latin-1 / Windows-1252 误解码的 UTF-8 文本还原，并在面板启动和 IndexedDB 恢复后批量修复已缓存数据。
3. **互粉评估体系普适化（v0.21.0 ~ v0.21.2）**：
   - 将关注/粉丝比例与互粉倾向结合评估，关注人数在粉丝数 `4/5`（差距 `1/5` 以内，即 `关注 >= 粉丝 × 80%`）视为**推荐**，差距超过 `1/5` 视为**不推荐**；
   - 支持通过主页前 5–10 条中英文帖子关键词（如 `串门`、`出摊`、`互关`、`互粉`、`回关`、`必回`、`多评`、`多互动`、`蓝V`、`follow back`、`mutuals`、`let's connect` 等）快速判定互粉意向，并支持 Grok 批量分析回填 `互粉 / 无` 标签；
   - 标签悬浮（hover）即时展示推荐原因或不推荐原因，去除了过于地域化的“骗关”表述。
4. **互粉追踪与定时拟人浏览自动关注（v0.22.0 ~ v0.24.0）**：
   - 将“互粉网络”升级为**“互粉追踪”**，拆分为 `已互关 / 已关注 / 待回关 / 无关系` 四个分类 Tab；
   - 增加表头全选、多选与已选计数徽标，使“批量更新”与“Grok 分析”支持按勾选账号定额执行；
   - 增加账号、简介与缓存帖子关键词搜索筛选；
   - 新增“互粉追踪 · 自动关注设置”抽屉，支持定时筛选有互粉意向/推荐标签的高价值用户，自动打开主页、模拟下拉阅读帖子并点击关注；
   - 统一关注记录时间戳与执行日志弹窗（查看看了谁、读了哪几条帖子、耗时与关注结果）。

## 二、核心功能迭代详述

### 2.1 粉丝管理：不定频增量检索与未互关批量取关

- **不定频定时检索（基准间隔 + 随机浮动）**：
  - 将早期固定批次的设置重构为侧边设置抽屉 `#settingsDrawer`，突出**检索基准间隔（分钟）**与**随机浮动（`±` 分钟）**，由 `background.js` 的 `x-followers-scan` 定时器动态计算下次触发间隔。
- **增量位点记录（`checkpointHandle`）**：
  - 在 `scanFollowersFromNetwork` 与 `scanFollowerList` 中记录最新粉丝位点 `monitor.checkpointHandle`。每次检索遇到上次位点，或翻页后整页都是已知粉丝，即自动停止，只拉取增量新粉；待回关队列按本次实际拿到的数据合并，不因批次数量中途停止。
  - 单次检索仍保留 `MAX_FOLLOWER_SCAN = 3000` 的安全上限（防止首次建基准时无限翻页），触顶时状态栏会明确提示。
- **“未互关” Tab 与批量取关**：
  - 在粉丝管理新增 `未互关` Tab（筛选我已关注对方、但对方未关注我的账号），表头首列放置全选复选框 `#listSelectAll`，并在“粉丝画像”列右侧显示 `已选 X / Y` 计数徽标，支持一键 `批量取关`（`network-api.js` 调用 REST 接口 `/i/api/1.1/friendships/destroy.json`）。

### 2.2 昵称/简介乱码自愈

- **现象**：部分账号昵称/简介显示为 `é˜¿å…°`、`åˆ›` 这类字符，属于 UTF-8 字节被按 Latin-1 / Windows-1252 误解码后存入缓存。
- **修复方案**：
  - `scoring.js` 新增 `repairMojibake(text)`：把每个字符还原为单字节（含 Windows-1252 `0x80–0x9F` 映射表），再用 `TextDecoder('utf-8', {fatal:true})` 重新解码；解码失败或本身是正常文本时原样返回，不误伤。
  - `panel.js` 的 `sanitizeMojibakeCollections()` 在面板启动、以及从 X 站点 IndexedDB 恢复数据后，批量修复 `monitor`、`mutualNetwork` 与 `profileCache` 中的昵称和简介并写回存储；列表筛选与评估时也会先经过 `repairMojibake`。

### 2.3 互粉意向识别、前 5–10 帖关键词匹配与推荐评估（v0.21.0 ~ v0.21.2）

- **推荐 / 不推荐量化标准（1/5 阈值）**：
  - 在 `scoring.js` 的 `evaluateMutualProfile` 中：
    - 当 `关注数 >= 粉丝数 × 0.8`（即关注数比粉丝数少在 `1/5` 以内，例如关注 4000、粉丝 5000）时，标记为 **`推荐`**；
    - 当 `关注数 < 粉丝数 × 0.8`（关注数比粉丝数少超过 `1/5`）时，标记为 **`不推荐`**。
- **主页前 5–10 条帖子中英文关键词快速匹配**（`MUTUAL_KEYWORD_PATTERNS` + `matchMutualKeywords`，扫描名称、简介与前 10 条帖子）：

  | 语种 | 标签 | 命中示例 |
  | --- | --- | --- |
  | 中文 | 串门 / 出摊 / 互关 / 互粉 / 回关 | `串门`、`出摊`、`摆摊`、`互关`、`互粉`、`回关` |
  | 中文 | 必回 / 多评 / 多互动 | `必回`、`有粉必回`、`秒回`、`多评论`、`常互动` |
  | 中文 | 蓝V / 加好友 / 多发 / 互助互动 | `蓝V`、`蓝标`、`扩列`、`日更`、`互赞`、`互浇`、`抱团`、`一起涨粉` |
  | 英文 | follow back / F4F / mutuals | `follow back`、`f4f`、`ifb`、`new mutuals`、`active mutuals` |
  | 英文 | let's connect / engage | `let's connect`、`grow together`、`support each other`、`drop your handle`、`stay active` |
  | 英文 | blue verified / make friends | `blue check`、`verified followers`、`road to 10k`、`make friends`、`visit my profile` |
- **普适化标签与即时 Hover 提示**：
  - 表格新增 **“标签”** 列：符合互粉意向且非“不推荐”的账号展示绿色 `互粉` 标签，其余展示 `无`；
  - 将原“骗关风险 / 无骗关风险”统一升级为普适化的 **`推荐 / 不推荐`**，并基于 CSS `data-tooltip` 实现零延迟悬浮气泡，清晰展示 `推荐原因：...` 或 `不推荐原因：...`。
- **Grok 批量分析自动回填**：
  - 提交 Grok 时附带关注/粉丝比与最近帖子，按标准行格式 `[@用户名 | 互粉意向: 有/无 | 互粉标签: 互粉/无 | 推荐评估: 推荐/不推荐 | 理由: ...]` 自动轮询解析并回填到本地缓存与 IndexedDB。

### 2.4 互粉追踪：全选定额操作、关键词筛选与定时浏览自动关注（v0.22.0）

- **四分类 Tab 与深色选中态**：
  - 互粉追踪拆分为 `已互关`、`已关注`、`待回关`、`无关系` 四个 Tab，修复 Tab 选中态深色背景与白字高对比度样式（`brand-layout.css`），并在操作列提供直接关注图标按钮。
- **全选 / 多选定额执行与关键词搜索**：
  - 表头首列新增全选复选框 `#mutualSelectAll`，`账号与简介` 列头右侧展示 `已选 X / Y`；
  - 勾选账号后点击 `批量更新` 或 `Grok 分析`，严格按已勾选的指定数量执行；未勾选时默认作用于当前页；
  - 子工具栏新增关键词搜索框 `#mutualSearch`，由 `filterMutualTrackingUsers` 支持按 `@账号`、昵称、简介、缓存帖子正文及互粉标签过滤。
- **定时获取有价值用户 · 模拟下拉看帖并点击关注**：
  - 新增右上角设置按钮 `#openMutualSettingsDrawer` 与设置抽屉 `#mutualSettingsDrawer`；
  - 支持配置定时周期（基准间隔 `every` + 随机浮动 `jitter`）、单次访问账号数、最低粉丝门槛、仅挑选有互粉意向/推荐标签开关、下拉看帖次数与每屏停留秒数；
  - 执行流程（`runMutualAutoFollowBatch` → `visitScrollAndFollowCandidate`）：
    1. 通过 `selectValuableMutualTargets` 筛选未关注且高价值的候选账号（优先待回关与带 `互粉`/`推荐` 标签账号，自动排除“不推荐”账号）；
    2. 在后台打开对方主页，调用 `simulateProfileScrollStep` 分段平滑下拉模拟阅读帖子并随机停留；
    3. 顺带读取前 10 条帖子复核评估，若复核发现属于“不推荐”则自动跳过；
    4. 确认高价值后滚回顶部调用 `clickAnyFollowOnProfile` 点击 `Follow / Follow back / 关注 / 回关`；页面按钮未就绪时回退 `followViaNetwork`（REST `/i/api/1.1/friendships/create.json`），并同步更新本地关系状态。
  - 调度链路：`saveMutualAutoFollowSettings` 创建 `x-mutual-auto-follow` 定时器 → `background.js` 到点后按 `every ± jitter` 重排下一次，并发送 `runMutualAutoFollowTick` → 面板 `chrome.runtime.onMessage` 接收后执行一批。

> [!NOTE]
> 自动浏览关注依赖管理面板页处于打开状态；面板未打开时 `background.js` 只弹出系统通知提醒，不会在后台静默执行。

## 五、v1.11.1：互关追踪网络展开（锚点收集）异常排障与修复（2026-10-21）

### 1. 故障现象与复现
在「互关追踪」列表行操作列中，点击任一账号的「以该账号为锚点，合并去重后的互关追踪列表」分叉图标按钮（例如对用户 `@QQ20C` 执行展开收集）时，网络收集阶段完成后抛出红色异常错误提示：
`@QQ20C 收集失败：Cannot read properties of undefined (reading 'has')`

### 2. 根因深度剖析
该错误出现在 `panel.js` 的 `collectMutualNetwork` 统计汇总阶段：
```javascript
const relationCounts = Object.groupBy
  ? Object.groupBy([...relationMap.values()].map(applyOwnFollowingSnapshot), personalRelationshipLabel)
  : [...relationMap.values()].map(applyOwnFollowingSnapshot).reduce(...);
```
- **JavaScript `Array.prototype.map(callback)` 回调传参陷阱**：
  `map` 调用回调函数时，会固定向其传递三个实参：`(currentValue, index, array)`。
- **默认形参与实参冲突**：
  `applyOwnFollowingSnapshot` 原定义为：
  ```javascript
  function applyOwnFollowingSnapshot(user, index = buildRelationshipIndex(monitor)) {
    return applyRelationshipSnapshot(user, index);
  }
  ```
  当作为 `.map(applyOwnFollowingSnapshot)` 回调直接传入时，形参 `index` 接收到的是数组的数字下标（`0, 1, 2...`）。由于 `0 !== undefined`，ES6 默认参数未被激活，导致数字 `0` 作为关系索引传入下层的 `applyRelationshipSnapshot(user, 0)`。
- **未定义属性读取崩溃**：
  在 `applyRelationshipSnapshot` 中，代码直接执行了 `index.following.has(key)`。因 `(0).following` 为 `undefined`，立即触发运行时异常：
  `TypeError: Cannot read properties of undefined (reading 'has')`。

### 3. 三层防御修复与架构加固
1. **显式包装回调传参**：
   在 `panel.js` 的 `collectMutualNetwork` 汇总逻辑中，将直接传参改为显式单参数箭头函数包装：
   `[...relationMap.values()].map(user => applyOwnFollowingSnapshot(user))`，杜绝数组下标作为参数隐式透传。
2. **面板层入口安全回退**：
   在 `panel.js` 的 `applyOwnFollowingSnapshot(user, index)` 中增加类型判断守卫：当 `index` 为非对象或缺失 `following` 集合（例如被意外作为数字下标传入）时，强制安全回退为 `buildRelationshipIndex(monitor)`。
3. **领域规则层（`relationship-rules.js`）零抛错防御**：
   在纯规则模块 `src/features/relationships/relationship-rules.js` 中：
   - `applyRelationshipSnapshot`：安全提取 `following` 与 `followers` 并在确保为合法拥有 `has` 方法的 Set/Map 时方才调用，其余分支安全降级，永不抛错；
   - `commentRelationshipLabel` 与 `monitorUserStatus`：全面使用可选链 `index?.following?.has?.(key)`、`index?.queueStatus?.get?.(key)` 规范安全访问。
4. **单元测试与全链路回归**：
   - 在 `tests/relationship-rules.test.js` 增加针对数组 `.map(rules.applyRelationshipSnapshot)`、直接传入数字 `0`、`null`、`undefined` 及空对象 `{}` 的回归单元测试；
   - 全仓库 438 项原生测试与 40 项工程构建测试 100% 通过（`npm test`、`npm run test:build`、`npm run check`）；
   - 在真实 CDP 调试实例中重新加载扩展并热刷新看板，版本号平滑递增至 `v1.11.1`，验证互关追踪与关系状态统计均正常渲染。
