# 队列回关日志分页错位排障

## 现象与现场证据

2026-10-25，关注队列持续执行，但“粉丝跟进 → 队列回关日志”显示的记录停在较早时间，容易误判为回关停止或日志丢失。现场读到队列任务 `fq_bbefbc22-75fc-4863-aad0-13adbca57b7a` 在 19:43:35 记录了 HTTP 429，状态为结果待核实；同一时段其他任务仍在执行。19:54:37 的队列日志和对应任务均记录了关注成功。

从日志数据库按时间倒序查找粉丝来源记录时，最近一条在全部队列日志中的第 81 条。旧页面只查询最新 30 条队列日志，再在浏览器中筛选粉丝来源，因此这一页会漏掉真实存在的回关记录；“本页记录数”也不能代表该分类总数。数据库时间使用 UTC ISO 值，界面换算为本地时间，19:43:35 对应 `2026-10-25T11:43:35Z`，这组时间本身没有八小时时差错误。

## 修复

- 在现有执行日志 IndexedDB 的范围索引中增加 `queueFans` 分类。写入队列日志时按 `sources.module === 'fans'` 建立分类；原有日志在一次性迁移中补齐索引。
- 页面按 `queueFans` 分类查询、分页和统计，避免其他来源的日志占满页面。原“关注队列”日志仍查询 `queue`，清空它时同时清除派生的粉丝队列索引，避免旧记录重现。
- 迁移保留已经清空的历史范围，不从旧备份重新补出被清空的队列日志。
- HTTP 429 的任务仍保持待核实；该错误不能作为已关注成功的证据，也不自动重复发送关注请求。
