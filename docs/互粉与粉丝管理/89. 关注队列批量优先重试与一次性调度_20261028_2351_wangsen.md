# 关注队列批量优先重试与一次性调度

## 需求与交互

在已有关注队列的“等待重试”筛选中，勾选本页记录后显示“批量重试”，列表顶部和底部均可操作。只提交所选重试记录，不复制任务、不扩大到所有搜索结果。已接收任务显示“优先重试”；全部入队成功显示 3 秒自动关闭提示，拒绝项保留具体原因。

## 调度与安全边界

复用 Dexie/IndexedDB 事务、现有统一调度器与 Chrome alarms，不引入第二套执行器。每条原任务持久化 manualRetryRequestedAt，领取时先选手动批次并原子清除标记。保留历史重试次数；失败按原有退避处理，一次点击不会无限立即重试。重复提交仍对应同一记录。

独立一次性闹钟唤醒同一执行器；有任务正在运行时等待，不抢占或并发执行。自动开关关闭时可手动执行这一批，且不领取未选中的普通任务、不打开自动开关。批次未完成时保留待领取记录并继续调度；执行核验、每日上限和时间预算仍生效。显式暂停会清除未领取的手动标记。重启后从持久标记恢复闹钟。

跨账号、已离开 retry、来源未启用、导入待核实及存在关注、移粉、生成或发布操作证据的记录拒绝直接重试，返回具体原因，保留待核实路径。

Chrome 官方说明建议持久化动态闹钟意图并在后台启动时检查恢复；本实现遵循该模式：[Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)。

## 文件

- follow-queue-store.js：批次事务、领取优先级、一次性标记与取消。
- follow-queue-scheduler.js：retryBatchOnly 限定本次领取范围。
- follow-queue-runtime.js 与 background.js：命令、持久恢复与独立闹钟入口。
- follow-queue-panel.js：既有勾选工具栏、入队反馈与状态。
