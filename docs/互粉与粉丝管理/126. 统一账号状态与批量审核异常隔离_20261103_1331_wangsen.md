# 统一账号状态与批量审核异常隔离

版本：4.27.0，开发迭代，未提交或发行。

## 问题

业务模块重复从 X 侧栏核验当前登录账号，页面短暂未完成加载可能被当成账号变化。截图中的目标稳定身份异常还有另一个来源：审核准备和本地结果写入阶段，单条粉丝记录被更新或清理后抛出的异常中断整批处理。登录账号状态与粉丝资料校验必须分开。

## 实施方案

- 账号模块是当前登录账号的唯一读取入口，启动及每分钟调度检查已有 X 页面；复用现有资料缓存，不打开用户主页。复用 Chrome alarms、storage 和项目侧栏读取器，无新增调度框架或依赖。依据：[Chrome alarms 官方文档](https://developer.chrome.com/docs/extensions/reference/api/alarms)。
- 当前账号结果持久化到 xAccountState:v1。侧栏缺失、页面未就绪和请求异常保留上次确认账号；只有明确新账号或登录页退出证据才更新或清空。
- 队列、审核移除、自动取关、私信、主页评论及发布页面读取统一快照；页面脚本的 ISOLATED 和 MAIN 世界均接收账号模块发布的结果。新标签完成加载后同步快照，不重复探测侧栏。
- 账号侧栏首次展示读取快照，手动刷新才主动触发账号模块；定时刷新结果通过存储事件更新显示。
- 单条粉丝资料缺失、ID 冲突或审核版本变化只跳过该条，其余继续。缺少资料仍按原规则待核实。目标 ID、操作回执、重复提交防护继续保留，不因本次调整错用其他用户资料或重放不明外部操作。
- 移除产品提示中的身份不稳定概念，改为具体账号资料、用户 ID 或记录变化原因。
