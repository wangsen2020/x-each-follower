## 产品语义

| 状态或操作 | 行为 |
| --- | --- |
| 自动核验 | 默认连续失败最多 3 次，包含首次核验；设置可调 1–10。按原调度周期执行，不在单轮内密集重试。 |
| 明确屏蔽或停用 | 直接进入待人工审核，不浪费剩余次数，不解除屏蔽。 |
| 待人工审核 | 持久隔离，后续轮次、候选重扫、后台重启均不再自动打开。 |
| 删除本地记录 | 删除所选账号在当前数据范围内的本地来源记录，成功后清审核状态；保留历史日志。没有禁止再次采集的标记，未来可能重新进入任务。 |
| 跳过 | 保留记录与按绑定账号隔离的去重标记，不再自动调度；已跳过列表仍可检查及显式重试。 |
| 重试 | 开放新的一轮核验预算，不直接发送 X 操作。若原操作结果不确定，保留原提交凭据，只恢复结果核验。 |

人工处理提供搜索、每页 10 条、跨页选择、当前页全选和批量动作。切换筛选或搜索重置选择；批量单条失败保留该条并继续其他项，失败明细可展开。删除前显示本地数据范围和再次进入任务的语义。

## 架构与复用

- 继续使用现有 Chrome alarms、按绑定账号保存的 autoUnfollowState 账本、记录服务和备份日志。审核状态只保存目标 ID、handle、名称、次数与原因，避免复制整份业务资料。
- 按用户 ID 去重；双方有 ID 时不按 handle 合并不同身份。绑定账号之间的审核和跳过状态独立。
- 发起主页核验前持久预留次数。最后一次核验途中退出，重启会转审核，不能靠中断恢复出新的无限预算。
- 已有 pendingItems 的 checks 达到上限时直接转审核；原操作次数、提交阶段和已用额度保留。仍未明确是否发出的请求不能被按钮直接重复提交。
- 访问接口的 User 返回只表示账号存在。是否屏蔽由当前登录账号的明确关系字段或主页精确用户 ID 的 unblock 按钮决定；不匹配简介、帖子或推荐按钮。
- 原生审核图标、tips 与抽屉复用 PanelIconButton、InfoTipLayer、ActionSettingsDrawer；删除确认采用原生 dialog 语义。
- 已评估仓库现有 p-retry 8 与其官方仓库。它适合进程内 Promise 重试，不提供跨 MV3 重启的业务审核、跳过去重和持久预算，因此本轮不新增重试库或另建通用任务框架。现有 Dexie/记录服务继续承担 CRUD、事务及备份；本轮只增加必要业务状态和本地删除入口。
- deleteLocalAccount 复用既有序列化来源删除及备份，不依赖账号可用性分析。它直接读取记录索引，避免 lookupAll 的 100 条限制影响删除；所属账号和目标 ID 变化会拒绝误删。
- 审核动作与调度共用运行锁；面板消息校验发送者、绑定账号、目标 ID 和记录时间，过期界面不能操作新状态。
