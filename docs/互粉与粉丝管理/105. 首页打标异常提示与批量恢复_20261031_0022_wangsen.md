# 首页打标异常提示与批量恢复

分支：feature/home-tag-recovery；隔离目录：E:/WebstormProjects/xfollower-tag-recovery。通过 git flow feature start home-tag-recovery 从 develop d5612e6 创建；develop 与远程一致，与 master 4.8.2 的文件树一致。运行现场为其他工作区提供的 4.8.3，不能把本分支构建当成已加载。

## 需求与根因

现场 5000 条记录包括 4695 条待打标、172 条打标中、122 条互关帖、11 条不确定。6 个旧打标批次持续返回会话、任务或接口不存在，但客户端把恢复错误一律当成 pending，调度反复查询旧任务；新采集继续增长。6 条评论生成也存在相同接口错误。用户本轮明确保留 5000 条上限，增加顶部红色异常提示、最多 3 次自动重试以及全量未打标的手动批量入口。

## 实现

- 复用 Dexie 事务、现有 Chrome 分钟闹钟和 automationHealth 提示组件，不新建通用调度框架。调查 p-retry（https://github.com/sindresorhus/p-retry）与 Dexie 官方事务文档（https://dexie.org/docs/Dexie/Dexie.transaction%28%29）：前者处理内存 Promise 重试，不能单独保存 MV3 后台重启后的次数和回执；后者已在项目接入，继续承担事务与持久化。
- AI 客户端保留结构化网络和 HTTP 错误。查询旧任务的 404 或本地回执缺失不再伪装成仍在生成；未知网络结果保留原回执，避免直接重发。
- 新的 tag-recovery.js 仅处理打标业务。每条记录首次尝试加最多 3 次重试；tagAttempts、tagRetryAt、旧批次引用和原始结果保存在 IndexedDB。断网时每 5 分钟检查连接，不消耗提交重试额度；恢复后继续。确认失败或打标超时可以为纯分类建立新批次，已发布评论不重发。
- 正常等待中的任务继续查询原回执；无异常码的等待超过 30 分钟会退出无限等待。达到重试上限后标为打标失败，并持续显示人工处理入口。
- 手动“批量打标”快照包含当前账号全部 pending、tagging、failed 记录，不受分页/筛选影响；有效 mutual、not_mutual、uncertain 标签不重新打标。每批最多 30 条，7400 字符预算不足时拆小批，仍复用同作者已确认标签。每次调度处理一批，下一次分钟闹钟继续，不要求页面保持打开。
- 手动任务与自动打标共用互斥锁；按钮重复点击不创建并行批次。暂停会关闭采集与打标调度，返回中的 AI 原始结果保留；再次批量打标处理当前剩余记录。评论开关不受影响。
- 未完成积压达到 90 条或正在手动批量打标时暂缓新采集，优先处理旧记录。仍保持每账号最多 5000 条，保留已有标签、草稿、发布证据；清理时保留有限的重试批次历史引用。
- 全局顶部红色异常条覆盖采集/打标、评论接口阻碍及重试耗尽，带“前往处理”和详情，复用原 30 分钟提醒机制；恢复后按账号和故障类型分别清除。通知点击正确进入首页跟评。

## 同轮补充：两个调度的快捷启停

采集与打标、首页跟评状态卡各新增电源图标，分别切换对应定时调度。绿色表示开启，aria-pressed 和可聚焦提示说明当前状态及操作。关闭不需要连接 AI，下一次执行和提交前的 guard 会遵守暂停；开启验证已保存的引擎、会话与当前账号，持久化后按已有随机间隔安排下次执行，不立即生成或发布。仅写目标调度字段，不用整份配置覆盖其他调度；采集开关关闭时同时暂停手动打标任务，再开启可继续原进度。

增加独立持久化、离线关闭、配置缺失、账号切换与手动打标暂停恢复的回归测试。真实 Vue 隔离页实际点击得到：采集开/评论关 → 两者关 → 采集关/评论开 → 两者开 → 采集开/评论关；AI 请求为 0。390px 界面电源图标、颜色、说明和换行均已检查。1415 项单测、57 项构建测试通过，源码检查与构建通过。仍共用本轮 4.11.0。
