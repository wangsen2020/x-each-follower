## 根因与引入位置

- network-api 的 state 判断将 following=false 或 followedBy=true 都映射成 follow_back。当前 OR 写法可追溯至 69f2bba（2026-10-16）；此前解析器已有“未关注即待回关”的简化约定，不能声称该提交首次创造了全部问题。c4511b2 仅把根目录源码迁入 src。
- 本地 fan-followback-policy 又将 pending/danger 或 follow_back 标签当候选证据；这些状态不代表当前关系。
- 队列按 fans 来源统一设 100，没有确认待回关子优先级。
- 实时关系缺字段时落入普通候选筛选，日志没有解释为什么未放行。

## 修复

1. 解析器只在 followedBy=true 且 following=false 时返回 follow_back；双方 false 为 none，缺字段为 unknown。粉丝列表对明确不再关注的已有档案同步 no_longer_following。
2. 待回关候选仅认双向明确关系。来源同步保存 followBackCandidate 并重算索引；确认候选优先级 200，其他粉丝来源 100，普通来源保持原有粉丝量权重。领取仍遵守冷却、租约和来源授权，执行前重新核验。
3. 实时关系缺字段进入 uncertain，发生于滚动和关注前；人工核验也不能以缺字段恢复 pending。已关注者不重复关注。
4. 确认待回关跳过比例和互粉意向筛选；保留原有放行开关含义，不新增身份类过滤。
5. 记录 relationshipDecision：双向关系、来源、用户 ID、核验时间、分流代码、放行开关与筛选原因。日志正文可直接看到；旧日志不补造关系。新一次执行不继承上次决策日志。
6. 最新执行已确认并非待回关时，不再因旧本地档案反复重启策略跳过任务。
