# 自动取关候选分页游标失效修复

创建时间：2026-10-26 12:06，Asia/Shanghai。准备版本：2.17.2。分支：feature/recent-feature-tutorials。

## 现场与影响

用户反馈自动取关日志在筛选超时账号阶段报cursor is invalid，目标账号未记录。读取当前扩展实际执行日志，轮次45434674-d2a2-46d0-8044-cc7d7e1b9d8f于2026-10-26 11:58:59失败，错误类型RecordCursorInvalidError，耗时1140毫秒；处理次数0、成功人数0，未进入目标账号取关。

当时下一轮计划已经排定，不是自动开关被关闭或每日额度耗尽。诊断时设置为每日200、单轮1、间隔3分钟和抖动1分钟、执行时段01:00至23:00。没有修改这些设置，也没有重试历史取关操作。

## 根因

auto-unfollow-adapter候选读取原来循环使用service.query的all页。record-runtime.query生成的界面游标绑定整个投影库revision。其他采集、关系更新或记录写入会提升revision，使下一页抛出RecordCursorInvalidError，即使候选本身没有变化。

它适用于界面一致性检查，但不适合作为持续有后台写入时的候选全量遍历。空闲时未必复现：本轮只读实机短暂采样期间revision未变化，旧游标仍有效；不能把间歇性成功当作不存在竞态。受控回归在首尾页之间写入另一模块，可靠复现旧分页失效。

## 复用现有能力

复用项目已有sourcePage和sourceOrder稳定键遍历，不引入新分页库、不重写数据库，也不放宽全局界面游标检查。现有能力已经按sourceKey、accountId、module、userKey推进，更新与显示排序或全库revision无关。参考[Dexie分页说明](https://dexie.org/docs/Collection/Collection.offset%28%29)。

新增readAutoUnfollowCandidates：先ready和summary刷新待同步记录，再分别遍历derived:tracker与unreciprocatedTracker，每页100。保持原查询的unassigned账号与unreciprocated模块范围；按规范化handle去重，真实跟踪记录覆盖同名推导记录。读取失败时抛错，不把半份列表交给动作流程。

这属于实时候选扫描，不承诺跨页事务快照。扫描期间新插入到已经过的键之前的记录，可在下一轮读到。选中后仍按原流程refreshCandidate，核验绑定账号、目标身份、关注关系、白名单和执行时段；没有直接以扫描结果执行取关。
