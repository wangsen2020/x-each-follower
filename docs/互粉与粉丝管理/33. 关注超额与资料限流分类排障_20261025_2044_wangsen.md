# 关注超额与资料限流分类排障

## 现场

2026-10-25 20:29 至 20:34，一轮关注队列中多个普通候选连续出现 `You are unable to follow more people at this time`，日志还显示了 X 返回的 HTML 帮助链接。任务留在结果待核实，但批次直到遇到 HTTP 429 才停止；仅该轮就有 16 个账号得到相同拒绝。随后有粉丝来源账号出现“用户资料接口限流，未发送关注请求”，浏览器主页可打开并不代表当时的资料接口可读。

X 官方错误码文档将错误 161 定义为账号无法继续关注，通常对应 HTTP 403，与接口请求频率的 HTTP 429 不同。X 的关注限制说明列出每日额度、短时关注过快、关注比例及账号受限等可能原因；单凭错误 161 无法判断具体哪一种。参考：

现场队列任务在 25 日当天已记录 349 次新关注成功，最近 24 小时 359 次；此数字只含本扩展队列，不含用户在其他设备或入口的关注操作。用户确认当天关注已超额，因此不应把“X 拒绝继续关注”归咎于某个候选账号的筛选结果。

- https://developer.x.com/en/support/twitter-api/error-troubleshooting
- https://help.x.com/en/using-x/x-follow-limit

## 改动

- 通过 X 返回的结构化错误码 161 识别账号关注限制；兼容旧响应中的英文文本，日志与任务详情显示中文分类，不再展示原始 HTML。历史记录在读取时转换展示，原始存储不改写。
- 错误 161 停止当前批次，对受影响账号保留结果待核实和响应状态；不把拒绝当作关注成功，也不自动重复发送关注请求。
- 资料读取接口 HTTP 429 在未发送关注请求时结束当前批次，当前账号保留可重试状态；日志明确区分“资料未读到”与“关注被拒绝”。
- @1hsntnc 的现场任务先因资料接口 429 进入重试，随后一次关注请求被 X 的错误 161 拒绝，现为结果待核实；两条日志对应不同尝试，不能只凭先前的资料读取失败推断最终状态。
- 旧关注入口也识别 161，避免在同一轮继续尝试；不恢复固定时长的全局冷却。下一轮仍按用户已调整的调度间隔执行。
