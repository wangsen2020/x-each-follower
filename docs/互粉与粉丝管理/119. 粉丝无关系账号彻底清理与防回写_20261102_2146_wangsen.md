# 粉丝无关系账号彻底清理与防回写

## 范围与保留规则

本轮用户明确要求粉丝管理只保留存在任意一侧关系的账号。following 或 followedBy 任一为 true 即保留；已确认二者均为 false 时清理粉丝业务记录；缺字段、无核验时间的默认 false、同时间矛盾和稳定 ID 冲突继续待核实，不能将未知当作无关系。封禁或不存在以当前最新可用性证据为准，晚于封禁证据的正常状态优先。

归属限定当前绑定账号，以及经确认属于该账号的历史 unassigned 记录。其他账号和身份不一致的同名记录不清理。无关系只清理粉丝来源、跟进和无独立用途的资料缓存；评论或其他模块有独立用途的记录保留，混合队列只移除 fans 来源。封禁账号清理当前归属的业务记录。保留必要的操作审计、恢复日志和最小删除标记，它们不作为粉丝档案展示。

## 根因及修复

- 原来无关系分类只从活动列表隐藏，底层多桶记录仍在。
- 旧停用清理使用 v2 完成标记跳过同一证据，不能证明当前无残留；现在每次重查真实记录，不再依赖旧标记。
- 删除错误复用写入的 payload 归属校验，带账号的删除请求缺少正文时会失败；删除按复合账号主键校验。
- 删除增量日志缺少 accountId，重建时可能落回 unassigned 而无法删除原记录；现补全归属，覆盖单条与批量删除。
- 清理先保存逐账号最小删除标记，再删业务记录；重放、旧任务写入和批量入库均检查标记。新的有时间戳的真实关注或粉丝关系允许重新入库，新的不同稳定 ID 不被旧身份标记阻断。封禁账号有更新正常证据可恢复。
- 标记使用现有增量日志服务逐项持久化，不在每个日志里复制整个标记表；队列与资料补采仍复用已有事务服务。若记录清理成功、队列失败，持久标记会把账号带入下轮清理继续处理。
- 任务正在执行、租约未结束或评论正在处理时延后，不中断外部操作。关系核验发现 false/false 后通知清理，不再安排该账号的帖子补采；启动、可用性变化、五分钟定时扫描负责修复历史积存。

## 关键实现

- src/features/relationships/fan-retention.js：关系、可用性、归属和陈旧写入判定。
- src/features/records/record-runtime.js：候选枚举、复核删除、增量标记和恢复。
- src/features/relationships/unavailable-cleanup.js：记录、队列和资料任务协调，持久进度 fanRetentionCleanupStatus。
- src/features/follow-queue/follow-queue-store.js：粉丝任务删除与混合来源剥离。
- src/features/relationships/fan-profile-collector.js：清理待补采及历史任务，并保护执行中项。
- src/entries/panel/panel.js：删除“无关系保留历史记录”的过时状态说明。
