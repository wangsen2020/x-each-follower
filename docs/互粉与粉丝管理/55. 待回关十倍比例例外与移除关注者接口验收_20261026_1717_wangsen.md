# 待回关十倍比例例外与移除关注者接口验收

创建时间：2026-10-26 17:17 · 作者：wangsen · 目标版本：3.1.0

## 规则

用户最终确认：关注数×10%大于粉丝数，即关注数严格超过粉丝数10倍时，不回关并移除此关注者。仅在待回关放行开启、粉丝来源、实时确认对方关注我且我未关注对方时执行。等于10倍继续放行；计数或关系未知时待核实。比例是用户配置的排除依据，不作为已证明机器号的身份结论。

## 接口复用

调研原始开源示例确认存在 `RemoveFollower` mutation，变量为 `target_user_id`：https://gist.github.com/cyrillsemenov/e9b014a68e4a2c1c2a1c175b8314f3de 。此示例仅用于核对请求形状，不复制其批量循环、硬编码凭据或接口ID。既有 `network-client.js` 已有DeleteTweet的动态元数据发现、会话模板、签名和脱敏能力，本轮只扩展允许的mutation及目标变量，不引入另一套网络层。

用户追加要求使用network API；因此最终操作通过接口提交，主页仅承担登录账号、目标身份和关系核验。

## 持久化与验收事务边界

提交前必须保存移除意图到原队列任务的 `followResult.followerRemoval`。调度器将该意图视为可能产生外部作用；中断后进入待核实，禁止自动重新提交。成功后记录excluded，未明确成功保留uncertain。

单账号CDP验收复用项目现有 `createFollowQueueStore`，不直接重写IndexedDB CRUD。`resolveJob`在同一读写事务内更新jobs、outcomes、meta及修订号；沿用原实现对jobs、outcomes、settings、meta四个store的事务串行范围，仅改任务、结果和修订记录，不改settings内容，不清空队列。前提为已绑定正确账号、队列暂停、目标任务没有有效运行租约。验收仅改变用户指定的KYCGoat123任务；已有运行任务、其他候选和原配置均保留。

未提交前的目标身份、实时关系或计数变化会阻止提交。已提交而响应丢失时先核对关系，禁止重试。生产路径和单账号验收均使用同一比例策略、操作适配器与原有持久化方法。
