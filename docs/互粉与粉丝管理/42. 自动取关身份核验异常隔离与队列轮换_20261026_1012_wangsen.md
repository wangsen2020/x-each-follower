## 现场与原因

2026-10-26，自动取关反复停在 `hid65628262`。CDP 只读检查发现：本地超时记录仍保存用户 ID `1571543633765011456`，X 目标主页正文显示“此账号不存在”，页面捕获的原生资料响应为 `{"data":{}}`。运行扩展为 2.16.4，磁盘已有其他需求的 2.16.5 构建。

适配层收到 HTTP 200 后找不到目标用户，即抛出无错误代码的“目标账号身份无法确认”。协调器将其作为整轮致命错误，未推进队列，因此下次再次命中同一目标。空资料不能证明账号已封禁、已取关或永久不存在。

## 实施范围

- `auto-unfollow-adapter.js` 区分资料未返回目标与真实 ID 不一致，附带错误代码、本地 ID、实时 ID。
- `auto-unfollow.js` 仅在候选账号的首次操作前核验处，隔离上述两类错误及现有 `X_PROFILE_UNAVAILABLE`、`X_PROFILE_IDENTITY_UNRESOLVED` 错误。该账号不操作，保留记录和历史，移至队尾，本轮继续核验后续候选。
- 跳过不预留额度，不写入已取关，不自动修改本地身份与关系。日志逐条说明目标、原因、ID、未操作及队尾待核实状态。
- 登录账号不一致、网络与 HTTP 错误继续停止本轮。核验上次 pending 操作位于隔离逻辑之外，身份不明时继续阻断，禁止绕过不确定操作。
- 保留原有每轮最多一人、每日额度与核验数量规则；本次没有新增限制或修改用户设置。

## 复用与边界

检查现有依赖 Dexie、既有持久队列与 profile-access 错误分类，并查阅开源项目 [x-unfollowers](https://github.com/kysoog/x-unfollowers) 与 [X 错误文档](https://developer.x.com/en/support/twitter-api/error-troubleshooting)。本次缺口是项目协调器把单目标失败升级为全轮失败，复用现有队列和分类即可；未新增通用调度库或重建存储设施。上述资料不构成空资料响应的账号状态证明。
