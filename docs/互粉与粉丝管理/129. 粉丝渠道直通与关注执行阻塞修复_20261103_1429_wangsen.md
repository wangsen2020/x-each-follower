# 粉丝渠道直通与关注执行阻塞修复

版本：4.28.2；包含 4.28.1 直通优化及后续关注职责修正。

## 现场与原因

实机 4.28.0 已开启 followBackSkipRules。14:14 的 willsinginh 任务有粉丝渠道审核凭据，同时包含互关来源；实时关系 followedBy=false 导致旧逻辑拒绝粉丝跳过，退回普通筛选，扫描 20 条帖子并提交队列 AI。该轮在部署暂停时中断检查点，错误记为失败并退避重试。

只读队列发现 86 个待执行粉丝渠道任务，调度记录停留 sync-candidates。旧实现执行前等待 monitor、mutualNetwork、commentTracking 全量同步，串行扫描阻挡已入队粉丝。

## 修复方案

复用现有审核 grant、队列调度器、单任务租约、IndexedDB、评论 worker 和全局访问预算；不新建调度基础设施。

- 开启跳过粉丝时，粉丝渠道有效 grant 与最新审核状态一致即可跳过重复过滤、比例判断和队列 AI。是否仍关注我不改变已授权关注，仍核对目标 ID、账号归属、撤销审核、排除标记、关注请求与已有操作回执。
- 已有可执行队列时，来源同步在后台进行；初次空队列仍等待同步。重复同步调用合并为一个在途任务，避免串行积压。
- 已放行粉丝的执行前读取不抓帖子；先关注并保存成功检查点，再准备评价帖子。评价发布继续由原评论 worker、配置及访问预算控制。
- 主动暂停且没有外部操作时保留 pending，不增加失败次数或指数退避；已有操作结果不明仍保留 uncertain。
- 设置标签改为跳过粉丝，说明放在可聚焦 tips 中。默认值与用户已保存开关不变。

## 验证

### 4.28.2 关注职责修正

已入队任务不再以对方是否仍关注我作为执行条件，普通执行、提交前检查、核实回写三处统一。对方取关或反向关系字段缺失不会取消任务；该字段不再参与队列 AI 输入摘要，审核过程中取关也不会导致重复审核。粉丝列表采集仍按真实关系分类，关注后的回关情况由回关监控处理。

提交前只读当前主页按钮，不额外打开主页或滚动取帖。目标 ID 一致的关注／回关按钮可补齐 API 缺失的自身关注状态；已关注完成，待确认保留请求不重复发送，页面或接口明确不存在／停用则结束。缺少自身关注状态、目标 ID 不一致及已有未确认提交仍保留检查，防止重复或错账号操作。

回归覆盖反向关系为否／缺失、审核中取关、核实不撤销入队、目标按钮补齐字段、提交前按钮变为已关注／待确认、页面与接口不存在／停用。完整单测 1,883 项、构建测试 58 项全部通过；源码检查 201 模块及 244 个 JS/Vue 文件通过，构建 61 文件校验完成。

实机面板与后台均已加载 4.28.2，关注队列、自动审核、自动核实及自动取关配置已恢复，跳过粉丝保持开启。原列表搜索及核实日志弹窗保留。设置界面在 1280 × 900、390 × 844、640 × 450 验证保存回读、键盘提示及无横向溢出，已审视设置及实机 1920 × 911 截图，分别保存在 C:/jtmp/xf-fan-priority/ui/ 与 C:/jtmp/xf-fan-priority/live-4.28.2.png。

4.28.1 上一实际轮次最终新增关注 4 人、失败 0，随后资料接口限流结束；4.28.2 本轮仅加载及只读验收，没有强制追加真实关注测试，按原定时调度继续执行。历史已排除记录未批量重新入队，避免重放包含已失效账号的旧任务。
