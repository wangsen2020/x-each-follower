# AI 连接统一检测与设置提醒

本轮属于 feature/fan-review-flow 的连接恢复与设置反馈迭代，目标版本 4.32.0。保留现有未提交变更；主目录旧源码不参与构建。

## 问题与方案

粉丝审核设置、知识学习、业务提交分别读取远程会话，页面另有 8 秒超时，产生不同的连接结论。账号设置侧统一管理本地 AI 引擎状态：后台监控保存安全快照，其他模块只读取快照和会话列表。复用现有 AgentRelay 客户端、Chrome alarms、Dexie 配置和 Vue 组件，不增加通用调度框架。

正常每 5 分钟检测，失败每 1 分钟重试；相同引擎并发检测合并，健康检测不发送测试消息。账号设置图标上方展示异常、重试入口及倒计时，恢复后自动消失。未配置引擎不当成故障。设置连接测试仍由账号设置显式发起。

业务任务失败和服务连接失败分开：原任务继续按原编号查询，禁止因监控重新提交。业务模块不再主动探测网络。配置变更后旧检测不得覆盖新状态。日志与公开快照不得保存 Token。

## 验收计划

覆盖并发合并、定时恢复、未配置、配置变更、后台重启及只读消费者；回归原任务恢复、全部单元测试与构建。真实浏览器检查正常状态、隔离故障浮窗与倒计时、窄屏。保护在途任务，空闲窗口才加载构建。

## 实施与验收结果

- 账号设置侧新增 ai-connection-state 单一状态所有者，复用 Chrome alarms 和现有传输层；后台启动恢复定时器，启动期业务准入等待同一份检测，避免尚未完成检查就误报失败。
- Grok Local、Codex、Antigravity 业务适配器共用状态、会话缓存；生成任务不再请求 sessions；原任务恢复不经过新任务准入，不重发。
- 粉丝配置、审核配置、知识学习移除独立检测入口，订阅统一状态更新。设置图标提醒使用既有 Lucide 图标和键盘可读 tips，通过 Teleport 避免侧栏裁剪，窄屏保留账号设置入口。
- HTTP 200 但健康内容表示不可用仍判异常；未配置不告警；配置在检测中改变时拒绝旧结果。快照不保存 Token，用户输入和生成会话不被后台状态覆盖。
