# 26. 不可用账号自动清理与防重入

创建：2026-10-25 11:26 · 作者：wangsen · 版本：2.14.0

## 需求与方案

将此前人工清理接入后台。仅接受已有 not_found、suspended 证据和有效 checkedAt；不把身份待核实、超时、限流或错误文案作为删除依据。注销沿用已确认 not_found 证据，不从资料缺失推断注销。

复用现有记录删除、增量备份和队列删除服务。Chrome storage.onChanged 触发，启动及五分钟本地维护兜底；运行中、租约未释放或正在评论发布的任务延后，服务失败保留下轮重试。记录服务在删除前重新比较最新证据，同时间冲突及较新正常/待核实证据阻止自动删除。已完成证据按账号和 checkedAt 记录进度，避免反复处理。

队列删除保留防重入标记，确认时没有队列任务也写入 handle 标记。执行日志保留；不创建 X 主页、不调用资料或关系查询、不发送关注、取关或私信。跨存储删除非单一事务，中断可能暂时只完成记录或队列一侧，完成标记在两侧成功后写入，依靠重试收敛。

## 依赖与实现

检查现有 Dexie 与记录服务后复用，不另造 CRUD 或任务调度系统。自有 unavailable-cleanup.js 仅承担证据判定和已有服务调用的业务协调。参考 [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage) 与 [Dexie 文档](https://dexie.org/docs/Dexie.js)。

关键文件：src/features/relationships/unavailable-cleanup.js、src/entries/background/background.js、src/features/records/record-runtime.js、src/features/follow-queue/follow-queue-store.js。

## 验收与边界

真实扩展 origin 受控后台事件验收：隔离的 excluded 测试任务收到 not_found 证据后自动移除，持久化完成记录及防重入标记；另一个 uncertain 测试任务收到 identity_unresolved 后保持原状态。测试任务与证据已清理，没有向 X 发请求。记录实际删除能力复用此前人工清理已验证的服务；本次事件用例没有注入真实业务档案，不声称对真实账号进行新的封禁验证。

回归覆盖已确认清理、较新证据保护、运行中延后、失败重试、无任务防重入及不同所属账号隔离。浏览器已加载 2.14.0，五分钟清理闹钟存在，原自动调度已恢复。

完整工作区回归852项、构建检查49项通过；浏览器调用契约检查通过。计数是当时整个工作区测试结果。未提交、推送或发行。
