# 用户名变更后的关系核验与历史保护

## 问题与边界

X 用户名可能变更并被其他账号使用。本地不同来源保留同一历史用户名时，不能把两位账号的关系或队列历史合并。粉丝目录按当前用户名展示；安全核验以 X 返回的用户 ID 区分身份，ID 不完整或候选不明确时继续保留待核实。

## 修复

- 核验遇到同名不同 ID 时，先在本地查找旧 ID 的其他用户名，再向 X 核实该用户名当前确实属于同一 ID；仅当候选唯一且原用户名有当前用户记录时，移动旧来源记录到已核实的新用户名，并保存曾用用户名。
- 重命名时刷新新旧用户名的派生目录，更新失败或进程中断时记录待刷新用户名；增量重放同样刷新两侧。
- 先为当前用户名标记历史身份冲突，再移动旧记录；对未绑定 ID 的旧队列任务，核验与候选同步均不自动归属或修改，避免错误合并历史。
- 原始记录按原有备份和增量机制保存，不删除历史；无法验证的新用户名不自动修复。

## 验收

- 自动化：完整测试 1238 项通过；改动后的关系核验和记录回归测试 76 项通过。构建与源码检查通过。
- 真实账号：核验 `@666Q0` 与 `@666Q0_`，两者分别显示为已互关；旧关注来源迁移到 `@666Q0_` 并保留曾用名。`@666Q0` 未绑定 ID 的历史队列任务保持原样，不归并到新账号。
- 此保护会保守跳过该历史任务的自动归属；后续若要将它明确关联到旧账号，应另行核查任务来源和历史，不能仅凭用户名推断。
