# 24. 用户身份待核实标记与请求拦截

创建时间：2026-10-25 03:24。版本：2.12.8。

## 需求与判断

快捷私信提示无法确认用户 ID 时，旧逻辑只报错，其他入口仍可能继续请求。新需求采用持久化标记并停止自动请求；不能仅凭 ID 缺失将用户判为封禁、注销或删除数据。

现场只读查看已打开的 @Tomdvdzpzu 页面，emptyState 显示“此账号不存在”。没有重新导航或发送资料请求；已将该账号按 not_found 记录在扩展本地可用性存储中。

## 行为

- 资料请求成功、无接口错误但缺少匹配用户的有效 ID 时，快捷私信和关注队列持久化 identity_unresolved，界面标签为“待核实”。HTTP 错误及接口错误仍走原错误处理，不据此误标封号。
- 共享访问检查在创建主页标签和请求资料前拦截该标记，跨入口和重启后仍有效。队列进入待核实状态，不继续自动重试。
- 回关监控显示待核实图标及提示，禁用私信和取关操作；不把待核实当作允许删除的不可用证据。
- 用户点击状态图标可手动重新检查。只有取得有效用户 ID 的正常资料证据才解除身份标记；仅看到可访问页面但没有 ID 时保留标记。确认不存在或封禁则沿用不可用账号处理。
- 已存在的 not_found、suspended 可用性缓存及删除规则保持原边界；本次没有批量删除历史记录。

## 实现入口

profile-access.js 负责共享标记与前置阻断；panel.js 负责快捷私信标记、回关监控提示和手动检查；followback-monitor.js 合并标记但不将其视为删除证据；follow-queue-runtime.js 将身份无法核实的任务置为待核实。

## 验收

839 项核心测试、49 项构建检查及浏览器调用契约检查通过。新增回归验证标记持久化、多个入口零请求拦截、不完整正常证据不能解除标记、有效 ID 可恢复，以及待核实不等于封禁或允许删除。

使用真实扩展 origin 存储与源码访问适配器做受控验收：临时测试账号标记后，主页创建和资料请求均返回 X_PROFILE_IDENTITY_UNRESOLVED，实际分发次数为 0；测试键已清理。此项证明存储和共享访问入口行为，不是一次真实私信发送验收，也未触发关注或取关。
