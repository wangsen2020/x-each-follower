### 13.1 原因与处理

Chrome错误页仍可能具有complete状态，不能据此判断可注入。原初始资料循环吞掉注入异常直到超时；X本地备份还会缓存借用的标签页，错误后继续复用。定时通知直接显示底层英文错误，缺少账号与步骤上下文。本次确定这两类代码缺陷；没有将其断言为此前截图的唯一网络根因。

- 页面主框架失效时立即结束当前步骤，不反复注入。关注前按原有5/15/60分钟退避重试；已发送关注或发布的任务不自动重发，已成功关注的结果保留，发布待核验仍保持待核验。
- X备份缓存淘汰错误页，5分钟内不再借用；优先选择已完成的健康候选页面。只读操作最多换页重试一次，写入不自动重放。不会刷新或关闭用户借用的页面。
- 来源同步失败不再阻断已有队列任务；每项任务仍重新检查当前登录身份。结果回写失败单独记录，不撤销已确认的关注状态。外层异常、下轮调度异常均保留诊断；重复run互斥。
- 通知为中文，附账号、阶段和短诊断编号。同一账号/错误类型/阶段10分钟内合并异常通知；每次异常仍逐次记录。

## 2.11.0 关注与评论独立执行

2026-10-24：原先关注执行器在关注成功后同步生成和发布引用评价，评论消耗关注批次的时间预算。2.10.7 增加的 Grok 额度标记还会结束整轮关注，冷却检查会拦住下一轮。

现将关注执行器限定为账号核验、本地风险规则、关注和保存评论意图。Grok 账号风险研判、最近五帖择一、生成、发布和发布核实全部在独立评论执行器中进行。关注条件仍含本地风险过滤与已有明确风险证据；不再等待在线 Grok 审核。

- 独立定时器 x-independent-comments 每分钟检查已关注记录中的待评论意图；是否执行由 grokEnabled 控制，自动发布仍由 autoPublish 控制。暂停关注不等于暂停评论，关闭 Grok 评价开关停止自动评论取任务。
- 关注成功和评论意图通过原有队列持久化结算保存。评论执行器只写 evaluations，不修改关注状态、关注重试次数或关注批次时间预算。
- 评论额度耗尽保留待评论状态及 retryAt，15 分钟是重新检测间隔，不是假定的额度重置时间。失败或超时单独标记，可独立重试。
- 评论最多执行三分钟；超时发出取消信号，发布前重新核对信号、绑定账号、页面登录身份和任务是否存在。底层未返回的生成请求可能稍后结束，但不能在取消后进入发布。
- 同一账号任务的手动与自动评论共享评论互斥锁，与关注锁分开。持久化 publishing 后再提交；重启遇到 processing 或 publishing 时转为待核实，禁止自动重发。
- 最近五帖候选随评论意图保存，异步生成仍可择一或跳过，选帖后沿用同一个评论任务 ID。
- 评论日志使用 comment 范围；关注日志继续使用 queue 范围。
