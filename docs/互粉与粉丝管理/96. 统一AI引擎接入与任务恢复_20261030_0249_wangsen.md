# 统一 AI 引擎接入与任务恢复

本轮新增 Grok Bot、Codex、Antigravity 统一设置与业务接入，开发版本为 4.7.0。通过 Git Flow 在独立工作区创建 `feature/unified-ai-engines`，基于已发行 4.6.2 对应的 develop；主工作区 `feature/panel-table-scroll` 的 4.6.3 未提交 UI 修改完整保留，未覆盖、提交或发布。

## 接口与复用

复用项目原有 Grok 本机客户端的 Dexie 存储、任务回执和调用入口，提取为 `src/features/grok/agent-relay-client.js`，三个引擎使用同一传输实现。AgentRelay 服务端已有统一接口，因此仅增加前缀、会话字段与结果结构适配，不另建队列、任务服务或通用基础设施。沿用现有 Vue、PanelSelect 和 Dexie 依赖，未新增运行依赖。

| 引擎 | 业务配置值 | 接口前缀 | 提交会话字段 |
| --- | --- | --- | --- |
| Grok Bot | grok-local | /grokbot | sessionId |
| Codex | codex | /codex | sessionId |
| Antigravity | antigravity | /antigravity | sessionId |

统一接口读取 health、sessions，提交 jobs 并按原 jobId 查询，解析 `result.text`。旧 Grok `/bots`、`/jobs`、`bot` 字段和字符串结果继续兼容。X Grok 和 Grok Webhook 保留原有入口。

## 配置与任务保护

- 系统设置原 Grok Bot 栏目改为 AI 引擎；共用服务根地址与 Token，每个引擎单独保存会话及测试时间。Codex、Antigravity 的创建会话由用户显式触发。
- 采集打标、互粉评论、关注队列、知识库均接入引擎选择；知识库可以单独选择会话，避免随其他业务的默认会话切换。
- 数据库仍为原 `xfollower-grok-local`，不删除旧配置和任务。原 `config/local` 保留，新增共享连接行与每引擎配置行；修改连接只使不匹配的验证状态失效。
- 每个新任务在 POST 前持久化连接、协议、引擎、会话和任务号。恢复只查原回执，即使当前选择已变化，也不会改投新引擎或重复 POST。
- unknown 状态保留原任务；明确失败保留失败记录。Token 不进入公开 status、截图或业务文档。

## 设置体验

复用 PanelSelect。字段、按钮间距均为 10px，控件高 30px，左右表单列统一对齐，下拉箭头距右侧 10px。测试收到完整回复后显示“测试通过，连接和会话已保存”；失败不覆盖原配置。旧端口配置自动转换为服务地址显示。另提供会话读取、连接帮助和显式创建会话。

## 互粉记录保留

每账号上限由 1000 调整到 5000。首先保护正在打标、生成、发布中的任务，再保护互关帖，优先删除非互关旧帖；同优先级保留新记录。清理仍按账号隔离，保留采集锚点并清理无引用批次和过期扫描摘要。过去已被旧策略删除的记录不能凭新策略恢复。

用户最后要求暂缓处理 `must be defined`，本轮没有修改该错误的反馈及处理逻辑。诊断中单独打开首页窗口完成 3 页、140 条网络读取后关闭窗口，未复现该偶发错误；这不构成根因已修复的证据。
