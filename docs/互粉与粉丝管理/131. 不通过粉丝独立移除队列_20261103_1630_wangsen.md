# 不通过粉丝独立移除队列

版本：4.29.0。分支：feature/fan-review-flow。

## 用户要求

审核通过进入待回关与关注队列；不通过立即压入独立移除队列；资料不足进入待核实队列采集。生产者只等待持久入队，不等待上一条移除、审核批次或资料采集任务结束，不增加人工确认环节。

## 现场根因

人工与自动审核曾共用内联移除调用。外层审核在真正提交之前写入 attemptedAt，将访问冷却等未提交情况也变成未知操作。底层移除器遇到旧 attemptedAt 直接返回未知，既不查询最新关系，也不自动收尾；部分账号因历史未知回执被自动审核选择器排除。

## 实现

- 复用 Dexie 持久化任务，以操作账号和目标 User Rest ID 去重，按创建时间有序执行。独立 x-fan-removal-queue alarm 负责消费，当前执行期间可继续入队。
- 审核端接入 enqueueRemoval，仅持久化任务并返回。AI 与关键词不通过使用已有裁决，移除等待或限流不会将裁决改成资料不足，也不会重新调用 AI。
- 旧不通过记录自动扫描补入队列，未移除任务在冷却后继续；运行租约与事务防止并发重复消费。
- 真实移除意图由底层执行器在 X 写入之前记录。旧未知回执先查询最新 X 关系：已不再关注则直接完成；仍为关注者且等待期已过，复用既有执行器的账号、稳定 ID、关系核对后执行。
- 已移除只在取得绑定账号、目标 ID、关系确认时间后写入，保留移除历史。人工后续放行与账号切换阻止尚未执行的旧移除任务。
- 列表与结果卡显示“不通过 · 等待移除”，不再显示“移除待确认”。后台提供只读 fanRemovalQueueStatus 供管理面板核验。
