## 根因与引入位置

comment-worker.js 用 jobs.find 固定取第一条可处理任务，后续每轮仍从相同顺序开始。提交 218bded 在 2026-10-28 01:36 引入 Bot 待确认任务自动恢复，把 uncertain/bot_pending 纳入可处理条件，却未增加轮转。

如果队首旧 Bot 查询一直返回 pending，例如发送状态未知或原接口不匹配，任务仍满足下一轮条件，便会反复被选中，阻止后面的新任务得到处理。146830c 新增本地 Bot 后，本地任务同样进入该恢复路径。

使用旧 worker 源码运行新增队首阻塞测试可稳定失败；同一测试在修复后通过。现场顺序与可重现逻辑一致，但本轮没有为了复现而开启真实自动生成。

## 修复

1. 对所有可处理的评价任务，按最近评论处理时间轮转；旧数据依次回退到生成请求时间、队列创建时间。
2. 每次认领前通过原 resolveJob 事务持久化 commentAttemptedAt，重建工作器后也不会重置轮转。
3. mergeEvaluations 对该字段取非负最大值，防止旧回写或零值擦除已记录的轮次。
4. 保持每轮最多执行一条、原有串行与忙碌检查、发布证据检查和账号隔离。未改 IndexedDB 事务范围，也未修改数据库版本；新增字段为可选记录字段。
5. 旧 Bot 任务仍沿用 relayJobId 查询原请求，不换通道重发，也不把发布结果未知的任务纳入自动重试。

## 文案与设置

- 删除“仅推荐或互粉账号”入口，并移除 onlyRecommended 默认、规范化及重复判断。普通候选仍遵守最低粉丝数、关注/粉丝比和风险检查；确认待回关的既有分支保留。
- 该遗留开关在默认最低粉丝数下重复；移除后，明确设置最低粉丝数为 0 时，也不再有未展示的额外互粉意向否决。
- “Grok 自动创作”改为“自动生成内容”。提示明确概率、内容检查、草稿和独立发布开关；关闭生成不影响关注任务。
- 页头提示改为“自动生成已开启/已关闭”，暂停原因同步使用“自动生成”。
