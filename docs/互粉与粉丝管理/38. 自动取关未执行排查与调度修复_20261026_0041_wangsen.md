## 代码问题与修复

1. storage.onChanged 对整个 unreciprocatedSettings 的任意变化调用 schedule，重置取关闹钟。修改私信文案等无关设置也会推迟取关；频繁保存会造成持续延后。该监听逻辑可追溯至3cee187。现只在开关、周期、浮动、窗口变化时重排，其他更新保留已有闹钟；缺失闹钟仍恢复。
2. schedule 最小延迟原为5分钟，而 run 强制请求间隔30分钟。30±10配置可能在20分钟到期，然后被间隔保护拒绝。现计划下限同步为30分钟。
3. 原计划忽略执行窗口，在窗口外重复唤醒检查。现将落在窗口外的候选时间移至下一窗口起点，保留跨日/跨午夜支持；日志写入当前本地时间、最短间隔及下次计划。

普通重新比对当前保存记录元数据，不会每次写 unreciprocatedSettings。本次初步口头判断“每次检测重置闹钟”经调用链核对已更正；不能将确定的设置保存缺陷表述为已证实本次所有等待的原因。
