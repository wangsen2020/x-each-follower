# GSC 流量断崖排障复盘与 MCP 自动化接入实录

> 历史记录说明：本篇保留2026-10-21的排查材料。本次2.5.1仅将文档和技能纳入版本管理，没有重新核验GSC数据、授权状态或站点恢复结果；文中的镜像、内容质量等根因判断属于当时分析，不能仅凭索引状态或引荐域名认定因果。

本文档详细记录对 `goodexts.com` 及其全部子站遭遇搜索展现归零、排名断崖式暴跌的完整排查复盘，以及通过 CDP 实现 Google Search Console (GSC) 官方 API 与本地 MCP 自动化服务的全流程接入沉淀。

## 一、 事件背景与故障现象

2026 年 10 月中旬，站点 `goodexts.com` 及其子域名工具站点遭遇突发性的流量、展现量与关键词排名雪崩：
- **故障特征**：原有带来自然搜索流量的核心词（如 `download x video`、`x video 下载`、`descargar gif de x` 等 182 个关键词）在 Google 搜索结果中几乎全部丢失；
- **核心诉求**：
  1. 通过已有登录态的 Chrome CDP 会话直连 Google Search Console 控制台进行紧急诊断；
  2. 查明是否被 Google 人工惩罚、算法打击，或是配置失误；
  3. 将 GSC 官方数据能力接入为 AI 本地直接可调用的 MCP（Model Context Protocol）服务，形成长效运维工具与全局技能。

## 三、 深度根因归因分析（Root Causes）

### 1. 核心原因：主力功能子站首页全线掉索引（De-indexed）
通过 URL Inspection API 实机检测 `goodexts.com` 及其 3 个核心子站，得到了明确的索引覆盖状态：

| 站点 / 域名 | 实时覆盖状态 (`coverageState`) | 最近爬虫抓取时间 | 诊断结果 |
| :--- | :--- | :--- | :--- |
| **`goodexts.com`**（主站门户） | ✅ **`Submitted and indexed`** | 2026-10-10 | 正常索引，但本身为聚合页无词 |
| **`xdown.goodexts.com`**（下载工具） | ❌ **`Crawled - currently not indexed`** | **2026-10-14 15:10:56** | **核心受害者**，爬虫抓取后取消收录 |
| **`xblocker.goodexts.com`**（屏蔽工具） | ❌ **`Crawled - currently not indexed`** | 2026-09-30 12:25:13 | 首页未被 Google 编入正式索引 |
| **`xexport.goodexts.com`**（导出工具） | ❌ **`Crawled - currently not indexed`** | 2026-10-11 01:15:06 | 首页未被 Google 编入正式索引 |

> **定性结论**：全站展现断崖归零的直接原因，是贡献 90%+ 流量的 **3 个子站首页全部被 Google 降级为「已抓取 - 尚未编入索引」，被完全剔除出搜索结果池**。

### 2. 外部致命干扰：Cloudflare Pages 默认二级域名公网裸奔
在对 `https://xdown.goodexts.com/` 进行 URL Inspection 时，Googlebot 记录的引荐来源网址（`referringUrls`）明确暴露了：
- `https://goodexts-xdown.pages.dev/`
- `https://xdown-website.pages.dev/`
- `https://xdown-website.pages.dev/pt-br/privacy-policy`

#### 为什么会出现 `*.pages.dev`？
- 本地代码库位于 `E:\WebstormProject\xdown-website`（GitHub: `wangsen2020/xdown-website`）；
- Cloudflare Pages 连接 GitHub 仓库时，**强制且默认**根据仓库名分配一个二级域名 `<项目名>.pages.dev`；
- **致命机制**：绑定自定义域名 `xdown.goodexts.com` 后，Cloudflare Pages **默认不会关闭、也不会重定向默认的 `.pages.dev`**！
- 搜索引擎通过 SSL 证书透明度日志（Certificate Transparency Log）扫描并发现了这两个裸奔的 `pages.dev` 域名；
- 加上代码库中 `public/robots.txt` 写的是 `User-agent: * Allow: /`，未设置 `X-Robots-Tag: noindex`，导致 Googlebot 同时爬取到两个未封禁的 staging 镜像与正式域名，判定为低质模版站群，稀释了抓取预算并直接取消了正式站的收录。

### 3. 工具单页的“薄内容（Thin Content）”与 Nuxt 多语言稀释
- 3 个子站（下载器、屏蔽器、导出器）的核心功能均为纯前端 JavaScript 交互单页，静态文本字数稀少；
- 结合 Nuxt i18n 自动为各个工具生成了英文、中文（`zh`）、葡萄牙语（`pt-br`）、西班牙语（`es`）多套路径（全站共提交了 136 个 URL 到 Sitemap）；
- 大量多语言页面结构高度同质化且缺乏深度内容，导致 Google 判定全站内容增益过低，在 10 月中旬的系统质量重新评分中触发了门槛过滤（产生了 47 个 `Discovered - currently not indexed`）。

### 4. 二级子域名架构导致的权重孤岛
- Google 将 `xdown.`、`xblocker.`、`xexport.` 视为 3 个全新的独立站点；
- 在缺乏外部优质反向链接（Backlinks）的情况下，新子域名无法独立跨过 Google 严格的首页收录门槛。

## 四、 GSC MCP 自动化工程实施实录

为免去日后重复登录网页端查询的繁琐流程，本次通过 CDP 全自动完成了官方 API 接入，并开发了本地常驻的 MCP 服务。

### 1. 资产探测与凭据挂载
- CDP 自动进入 Google Cloud Console，确认项目 `wadesk-436602` 已开启 **Google Search Console API**；
- 探测到已存在的专用 Service Account：`gsc-daily-server@wadesk-436602.iam.gserviceaccount.com`；
- 在本机安全归档其密钥文件至：`C:\Users\Administrator\.gemini\mcp\gsc-mcp-server\service-account.json`。

### 2. GSC 权限自动授权（CDP 执行）
- CDP 自动导航至 `sc-domain:goodexts.com` -> **设置 -> 用户和权限**；
- 自动触发 `ADD USER` 模态框，填入服务账号邮箱，选择 **Full（完全权限）** 并提交保存；
- 刷新页面断言确认，`gsc-daily-server` 已成功列入授权用户列表。

### 3. 本地零依赖 MCP Server 实现
在 `C:\Users\Administrator\.gemini\mcp\gsc-mcp-server\index.mjs` 构建了基于纯 Node.js 内置模块（`crypto`、`readline`）的标准 Stdio JSON-RPC 2.0 协议服务，提供 4 大工具：
1. **`gsc_list_sites`**：查询当前账号授权的所有 GSC 域名与站点；
2. **`gsc_query_performance`**：按日期、页面、查询词多维拉取展现量、点击量、点击率及平均排名；
3. **`gsc_inspect_url`**：调用官方 URL Inspection API，实时诊断页面的 `coverageState`、`lastCrawlTime`、`googleCanonical` 及 `referringUrls`；
4. **`gsc_list_sitemaps`**：获取提交的全部 Sitemap 状态与已发现页面。

### 4. 全局配置与闭环验证
- 注册至全局配置文件：`C:\Users\Administrator\.gemini\config\mcp_config.json`；
- 双向握手与 API 测试全量通过（成功拉取 10/12~10/18 每日真实指标及 URL 诊断 JSON）。

## 五、 站点恢复行动指南（Actionable Recovery Plan）

针对上述根因，必须严格按照以下四步执行抢救恢复：

### 1. 立即阻断 Cloudflare Pages 默认域名（最高优先级）
在 `E:\WebstormProject\xdown-website` 中配置路由拦截，或在 Cloudflare 控制台添加重定向规则：
- **方案 A（代码级）**：在 `functions/_middleware.ts` 或 Nuxt 服务端中间件添加拦截：
  ```typescript
  export const onRequest: PagesFunction = async (context) => {
    const url = new URL(context.request.url);
    if (url.hostname.endsWith('.pages.dev')) {
      url.hostname = 'xdown.goodexts.com';
      return Response.redirect(url.toString(), 301);
    }
    return await context.next();
  };
  ```
- **方案 B（Cloudflare 规则级）**：在 Cloudflare Dashboard -> **Rules -> Redirect Rules**，针对 `xdown-website` 与 `goodexts-xdown` 设置：当 `Hostname` 包含 `.pages.dev` 时，强制 301 永久重定向至 `https://xdown.goodexts.com/`，切断重复抓取。

### 2. 扩充工具单页的实质性文字增益（打破 Thin Content）
在 `xdown.goodexts.com`、`xblocker.goodexts.com` 页面核心功能下方补充 800~1200 字高质量独特内容：
- **详细图文说明**：清晰的操作步骤（Step-by-step tutorial）；
- **FAQ 常见问答**：整合常见视频格式支持、隐私安全说明、法律免责声明，并配置 `FAQPage` 结构化数据 Schema；
- **多语言校对**：避免纯生硬机器翻译，降低低质机翻导致的 `Discovered - currently not indexed`。

### 3. 打通主站到子站的权威权重流动
- 在 `https://goodexts.com/` 首页及顶部导航栏，建立清晰的文字锚文本（如 "X Video Downloader"、"Twitter Block Manager"），直接指向子站点，传递首页的 PageRank 与爬虫权重。

### 4. 重新触发 GSC 索引审核
- 完成以上整改并部署上线后，直接使用已接入的 MCP 工具 `gsc_inspect_url` 确认页面连通；
- 在 GSC 控制台点击 **`REQUEST INDEXING`**（重新请求编入索引），通常将在 3~7 天内由 Googlebot 重新评估并恢复收录。
