XFOLLOWER / GROK HOOK

云端事件 Cloud Event
通过 Webhook 调用 Grok，
生成结果自动回传。

在 Grok 网页端配置一次自动化，用 Cloudflare 接收任务和结果，再把接口地址与连接 Token 绑定到 XFollower。照着做，或把整份实施指令交给 ChatGPT、Claude。

XFollower→Cloudflare Worker→Grok 网页自动化→结果回传
准备已登录的 Grok 与 Cloudflare 账号、支持 Webhook 的自动化功能。云端事件 Cloud Event 是自动化 Webhook 通道，仍使用 Grok 用量，不提供独立 Bot 额度。终端部署与附带测试使用 Node.js 22.13 或更高版本；手动网页配置无需安装 Node.js。

可选择 Grok 网页通道或 云端事件 Cloud Event 自动化通道。选择后直接使用对应文本通道，不跨通道自动重试未知结果。

推荐 / 自动接入

让插件完成配置

XFollower 3.7 起，在“系统设置 → 云端事件 Cloud Event”点击“开始接入”。插件会打开自己的配置页面，自动填写、读取数据和部署；下方固定代码保留为手动配置备用。

  1. 允许插件访问 Cloudflare 控制台，完成账号登录和必要验证。
  2. 插件预填部署令牌的权限与账号范围；核对摘要后点击“创建令牌”。无需复制令牌。
  3. 插件自动创建专用 D1 与 Worker，打开 Grok 自动化并填写名称、指令与 Webhook。遇到登录或安全验证时，手动完成后自动继续。
  4. 允许插件访问新中转地址，随后自动绑定并测试真实生成。HTTP 接收成功不代表完成，收到回传正文才显示“已连接”。

首次 Workers 开通可能需要确认条款和子域授权；向导会尝试预填可识别的子域字段。关闭面板保留进度，浏览器会话凭据失效后需重新授权。停止配置不删除已创建的云端资源。测试排队较久时继续查询原任务，不重复触发生成。

01 / GROK 网页端

创建一个专用自动化

  1. 打开 Grok 自动化任务，选择“新建自动化”，命名为“XFollower 文本生成”。
  2. 选择“添加触发器”→“Webhook”，保存任务。
  3. 重新打开任务，在触发器卡片中复制完整端点和签名密钥。端点通常是 https://grok.com/webhook/automation/…，签名密钥以 whsec_ 开头。
  4. 先保管这两项，完成 Cloudflare 部署后，回来粘贴第3步的固定指令。不要把签名密钥放进任务正文或插件。

执行入口是网页端自动化，不是桌面 Grok Bot。插件将这条 Webhook 文本生成通道命名为 云端事件 Cloud Event；它不提供额外订阅额度。

02 / CLOUDFLARE

部署自己的中转

推荐让有终端权限的 ChatGPT 或 Claude 按下方实施指令部署。全部代码在本页，Cloudflare 使用官方 Wrangler；你只需完成登录和私密值输入。也可以按下面的网页步骤手动配置。

  1. 打开 Workers 和 Pages，选择“创建应用程序”→“从 Hello World! 开始”。输入唯一名称并部署，例如 xfollower-grok-relay。
  2. 进入 Worker，选择“编辑代码”。将默认代码替换为本页“可直接粘贴的 Worker”完整代码，再部署。该文件已经包含签名库，无需在网页编辑器中安装包。
  3. 进入“存储和数据库 → D1 SQLite 数据库”，新建 grok-bot-relay。在数据库的控制台执行下方“数据库 SQL”。
  4. 返回 Worker →“绑定”→“添加绑定”→“D1 数据库”。变量名填写 DB，选择刚创建的数据库，保存并部署。
  5. 进入 Worker →“设置 → 变量和机密”，按下表添加配置。每项保存后，完成一次部署。
名称类型填写内容
WEBHOOK_URLSecretGrok 任务中的完整 Webhook 端点
WEBHOOK_SECRETSecret同一任务的 whsec_ 签名密钥
CLIENT_TOKENSecret独立生成的随机连接 Token，稍后填入插件
PUBLIC_BASE_URL文本本 Worker 的完整 HTTPS origin，例如 https://你的名称.你的子域.workers.dev；不带路径
BOT_NAME文本展示名称，例如 XFollower 文本生成

点击“生成连接 Token”会在当前页面本地生成48位随机值，只显示一次；复制到 Cloudflare 的 CLIENT_TOKEN 和插件的“连接 Token”。

此 Token 只授权访问你自己的中转，不是 Cloudflare API Token。刷新页面会清空这里的值；请保存在自己的密码管理工具中。

04 / XFOLLOWER
两项信息，完成绑定
  1. 回到插件 →“系统设置 → 云端事件 Cloud Event”。向导中的按钮也能打开本文和对应网页。
  2. 进入“绑定”，填写 Worker 的 HTTPS 地址，以及与 CLIENT_TOKEN 相同的连接 Token。点击“检查并绑定”，按浏览器提示允许访问该地址。
  3. 进入“测试”，点击“开始生成测试”。一次测试会产生一个真实任务。接口检查成功只是连接成功；收到生成结果才算回传验证通过。
  4. 验证通过后连接自动启用。本次由选择 Bot 打开的向导会自动切换为 云端事件 Cloud Event；也可回到 Grok 创作设置手动切换。
Token 不回显。重新绑定失败保留旧连接；新连接需要重新完成生成测试。解绑只移除本机连接，云端结果仍在自己的 D1 中，需要撤销访问时在 Worker 更换 CLIENT_TOKEN。


05 / 结果与恢复
核对一次完整任务
  • accepted：任务已接收，还没有得到结果。云端事件 的202也只代表接收。
  • completed：Worker 已验收回调并保存完整结果，插件显示“已完成”。
  • unknown：提交结果尚不能确认，保留原任务继续查询，避免重新消耗。
  • failed：确定失败，可以查看网页任务运行记录排错。
插件每30秒查询一次。等待超时、关闭面板或浏览器后台休眠后，原任务保留在“备用任务”中；重新打开这一页继续查询。生成结果只回到原有文本解析与质量检查，不直接执行发布等账号动作。

常见问题
现象处理方法
绑定返回401插件 Token 必须与 CLIENT_TOKEN 相同；不要填 whsec_ 或 Cloudflare API Token。
接口返回503检查 Secrets、PUBLIC_BASE_URL、DB 绑定及建表 SQL 是否完成并部署。
Grok 返回401WEBHOOK_URL 与 WEBHOOK_SECRET 必须来自同一个任务。更换签名密钥后同步更新 Worker。
202后没有结果查看网页自动化“运行”。核对固定 callback 和字段名；按原 jobId 继续查询，不重复点击生成。
回调返回400／413检查 jobId、token、result 的 JSON 类型及长度。结果应是非空字符串，不要把 JSON 对象直接当 result。
回调返回409同一任务已有不同结果或已失败。保留最初记录检查原因；不能用新结果覆盖。
查询返回404核对是否换了 Worker 或 DB。不要自动重发；先确认云端任务是否确实不存在。
Grok 用量耗尽等待对应额度重置，或按账号提供的可用方案处理。此通道不会创建额外订阅额度。
