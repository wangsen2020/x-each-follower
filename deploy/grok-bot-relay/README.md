# grok-bot-relay

Cloudflare Worker + D1 relay for the XFollower Grok Bot fallback channel. Interface contract adheres strictly to `docs/创作与发帖/70. Grok-Bot独立额度备用通道与配置教程方案_20261027_1709_wangsen.md`.

## Features

- **Protocol Version 1**: Implements `/v1/health`, `/v1/jobs`, `/v1/jobs/:id`, and `/v1/callback`.
- **Actual Webhook Contract**:
  - Webhook payload dispatched to Grok Bot: `{ jobId, text, callback, callbackToken }`, where `text` contains the original prompt.
  - Callback payload received from Grok Bot: `{ jobId, token, result }` (or `{ jobId, token, reasonCode }` on failure).
- **Strict Endpoint Validation**:
  - Validates `WEBHOOK_URL` is an HTTPS `grok.com` `/webhook/automation/` endpoint before dispatch.
  - Validates `PUBLIC_BASE_URL` is a valid HTTPS origin (without extra path, query, hash, or credentials).
- **Configuration & Schema Health Checks**:
  - `GET /v1/health` verifies Bearer client authentication, validates required configuration (`WEBHOOK_URL`, `WEBHOOK_SECRET`, `PUBLIC_BASE_URL`), and rejects missing D1 database schema with status 500.
- **Strict Webhook Acceptance**:
  - Webhook dispatch enforces `redirect: "manual"` and a 20-second timeout.
  - Only HTTP 202 from the webhook is accepted to transition a job to `accepted`. Non-202 statuses, redirects, timeouts, or network interruptions record the reason and mark status as `unknown` without blind automated retries.
- **Client-Aligned Limits**:
  - Jobs request body limit: 128 KB max.
  - Prompt limit: UTF-8 100,000 bytes max (matching client validation).
  - Callback result limit: 100,000 characters max.
  - Callback body limit: 256 KB max.
- **Standard Webhooks Signing**: Uses the official `standardwebhooks` library with HMAC signatures (`webhook-id`, `webhook-timestamp`, `webhook-signature`).
- **Parameterized SQL Queries**: All D1 operations use prepared statements with parameterized bindings to prevent SQL injection.
- **Race Condition Protection**: Atomic conditional status transitions protect against "callback arrives first" (`dispatching` -> `completed` before webhook HTTP response returns) and duplicate callbacks.
- **Strict Idempotency**:
  - Re-sending identical `jobId` + `prompt` returns current job status without re-dispatching webhooks.
  - Re-sending identical `jobId` with conflicting `prompt` returns `409 Conflict`.
  - Re-sending identical `jobId` + `token` + `result` to callback returns `200 OK`; differing `result` returns `409 Conflict`.
- **No Cache on Auth Responses**: Enforces `Cache-Control: no-store, no-cache, must-revalidate` and `Pragma: no-cache` on authentication failures and authenticated responses.
- **Credential Protection**: Constant-time token verification prevents timing side-channel attacks; query endpoints never leak callback tokens, hashes, or webhook secrets.

## Files

- `worker.js`: Production Cloudflare Worker entry point and route handlers.
- `schema.sql`: D1 table schema and indexes for `jobs`.
- `wrangler.jsonc`: Cloudflare Worker configuration, D1 binding `DB`, and public variables.
- `package.json`: Project scripts, dependencies, and devDependencies (including `wrangler`).
- `test/worker.test.js`: Comprehensive isolated unit and integration test cases.
- `test/d1-mock.js`: In-memory D1 test emulator using `node:sqlite`.

## Setup & Deployment

1. Install dependencies:
   ```bash
   npm install
   ```

2. Run automated test suite:
   ```bash
   npm test
   ```

3. Create D1 database and apply schema:
   ```bash
   npx wrangler d1 create grok-bot-relay
   # Paste database_id into wrangler.jsonc
   npm run db:init
   ```

4. Configure Cloudflare Worker secrets (never commit secrets!):
   ```bash
   npx wrangler secret put CLIENT_TOKEN      # Token generated by user for XFollower connection
   npx wrangler secret put WEBHOOK_URL       # Target Grok Bot webhook URL (https://grok.com/webhook/automation/...)
   npx wrangler secret put WEBHOOK_SECRET    # Webhook signature secret (whsec_...)
   ```

5. Deploy Worker:
   ```bash
   npm run deploy
   ```
